**Speedle Cloud はパブリックベータを提供中です。** このガイドでは、稼働中のサービスでの手順を説明します。

ロールの割り当ては通常ひとつのサービスに属します。複数のサービスが同じ割り当てを共有する場合は、アカウントの **グローバルロール** サービスに一度だけ定義し、各サービス自身の認可ポリシーでそのロールを使用します。

グローバルロールはロールポリシーのみを受け付けます。グローバルなロール割り当て自体は操作を許可しません。許可する権限は引き続き各サービスが定義します。グローバルロールはひとつの Cloud アカウントに属し、アカウントをまたいで適用されることはありません。

## ロールの割り当てを一度作成する

コンソールのサービス選択の先頭で **グローバルロール** を選び、ロールポリシーを作成します。

```text
grant user Emma from corp AdminRole
```

`from corp` は割り当てを `corp` ID ドメインに限定します。省略すると、リクエストのドメインにかかわらず Emma という名前のすべてのユーザーが一致します。[ID ドメイン](/ja/docs/idd/)を参照してください。

ロール `AdminRole` がアカウント内のすべてのサービスで Emma に割り当てられました。

## サービスで権限を付与する

権限が必要なサービス（例: `library`）に切り替え、認可ポリシーを作成します。

```text
grant role AdminRole borrow books
```

この操作を許可する各サービスでこの手順を繰り返します。独自の認可ポリシーがないサービスは、ロールが割り当てられていても何も許可しません。

## 結果を確認する

`library` の Playground を開き、`[{"type":"user","name":"Emma","idd":"corp"}]` を主体、`books` をリソース、`borrow` をアクションとしてテストを実行します。`AdminRole` により許可されます。`Bob` からの同じリクエストは拒否されます。

グローバルロール自身の Playground は異なります。グローバルサービス自体への判定は常に拒否されます。グローバルロールは各サービスの Playground で有効になります。

## 動作と制限

- グローバルロールはロールポリシーのみを受け付けます。グローバルサービスで認可ポリシーを作成すると `400 {"error":"global_authz_unsupported"}` を返します。
- グローバルサービスはアカウントのサービス上限に数えられ、そのロールポリシーはアカウントの合算ポリシー上限に数えられます。[制限とエラー](/ja/docs/cloud/limits-and-errors/)を参照してください。
- コンソールはこの特別なサービスを **グローバルロール** と表示します。手動での作成、名前の変更、削除はできません。
- アカウントの各 Speedle Cloud ADS インスタンスは、選択したサービス集合のみを同期する場合でも、常にグローバルロールポリシーを受け取ります。
- 変更は他のポリシーと同様に伝播します。公開スナップショット経由で約 1 分、現在の状態を直接読む Playground では即時です。
