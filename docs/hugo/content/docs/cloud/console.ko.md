**Speedle Cloud는 공개 베타로 제공 중입니다.** 무료 공개 베타는 평가와 학습용이며 SLA를 제공하지 않고 프로덕션 사용은 권장하지 않습니다. 기능과 한도는 변경될 수 있습니다.

이 매뉴얼은 [cloud.speedle.io](https://cloud.speedle.io/ko/)의 **Speedle Cloud Console(SCC)** 일상 작업을 안내합니다. 서버에서 빠르게 API를 호출해 보려면 [빠른 시작](/ko/docs/cloud/getting-started/)을 참고하세요. 요청 본문, 오류 코드, 할당량 상세는 [인가 API](/ko/docs/cloud/authorization-api/), [API 레퍼런스](/ko/docs/cloud/api-reference/), [제한과 오류](/ko/docs/cloud/limits-and-errors/)에서 확인할 수 있습니다.

> **스크린샷 안내:** 이 매뉴얼의 그림은 실제 Speedle Cloud Console을 한국어 UI와 데모 데이터(`example.test` 계정, `books` 예제 서비스, 예제 엔드포인트 및 사용량 수치)로 렌더링한 화면입니다.

## 로그인 및 콘솔 구성

### 사전 요구 사항

- JavaScript와 쿠키가 활성화된 브라우저.
- 이메일이 인증된 GitHub 또는 Google 계정.

### 로그인 또는 계정 생성

1. [cloud.speedle.io](https://cloud.speedle.io/ko/)를 열고 **시작하기**를 선택합니다(또는 `/login`으로 직접 이동).
2. GitHub 또는 Google 로그인을 선택하고 공급자에서 인증을 완료합니다.
3. 사용하지 않은 인증 이메일로 처음 로그인하는 경우 이용 약관과 개인정보 처리방침 링크를 확인한 뒤 **계정 생성**을 선택합니다.

**예상 결과:** 콘솔이 활성 워크스페이스의 **서비스 및 정책**(`/w/<workspaceId>/service`)을 엽니다. 새 계정은 사용자가 **소유자**인 **개인** 워크스페이스로 시작합니다.

**복구 방법:**

- **이미 사용 중인 이메일:** 해당 이메일에 이미 연결된 공급자로 로그인한 뒤 **계정 설정**에서 두 번째 로그인 수단을 연결하세요.
- **이메일 인증 필요:** GitHub 또는 Google 계정 설정에서 이메일을 인증한 뒤 다시 로그인하세요.
- **신규 가입 일시 중지:** 베타 신규 계정 한도에 도달했습니다. 기존 계정은 계속 로그인할 수 있습니다.
- **세션 만료:** 세션은 7일간 활동이 없거나 생성 후 30일이 지나면 먼저 도달한 시점에 만료됩니다. 다시 로그인하여 계속 진행하세요.

### 콘솔 탐색

로그인 후 콘솔은 두 영역으로 구성됩니다.

- **상단 바:**
  - **Speedle | Cloud** 로고: 활성 워크스페이스의 **서비스 및 정책**으로 이동합니다.
  - **워크스페이스** 전환기: 현재 워크스페이스 이름과 역할(**소유자** 또는 **관리자**)을 표시하고, 워크스페이스 전환 및 **워크스페이스 만들기**를 제공합니다.
  - **문제가 있으신가요? 언제든 알려 주세요!** 도움말 링크, **언어** 전환기, **계정** 메뉴(이메일 주소, **계정 개요**, **계정 설정**, **로그아웃**, **모든 기기에서 로그아웃**).
- **왼쪽 사이드바:**
  - **콘솔:** **서비스 및 정책**, **API 키**, **ADS 플리트**, **감사 로그** — 모두 활성 워크스페이스 범위로 동작합니다.
  - **워크스페이스 설정:** **멤버** — 워크스페이스 멤버십을 조회하거나 관리합니다.
  - **Cloud 문서:** 이 문서 사이트를 엽니다.

[![Speedle Cloud Console 상단 바의 워크스페이스 전환기 확장 화면과 왼쪽 사이드바](/img/cloud/console/ko/01-console-shell-workspace-switcher.png)](https://engine.speedle.io/img/cloud/console/ko/01-console-shell-workspace-switcher.png)

상단 바 **워크스페이스** 전환기를 연 콘솔 레이아웃과 왼쪽 사이드바(데모 데이터, 한국어 UI).

## 개인 신원과 워크스페이스

Speedle Cloud는 **개인 계정**과 **워크스페이스**를 분리합니다.

- **개인 계정**은 인증된 이메일, 연결된 로그인 수단(GitHub 및/또는 Google), 브라우저 세션, **개인 활동** 로그(`/account/audit`)를 보관합니다.
- **워크스페이스**는 서비스, 인가 및 역할 정책(**전역 역할** 포함), 사용자 정의 함수, API 키, ADS 플리트 인스턴스, 워크스페이스 **감사 로그**, 일일 API 할당량을 담는 격리된 컨테이너입니다.

> 현재 콘솔 UI의 일부 문구에는 여전히 "계정" 표현이 남아 있습니다. 리소스 한도, 정책, 서비스, ADS 인스턴스, API 키는 선택한 워크스페이스에 적용되며 개인 로그인 신원과 세션은 계정 수준으로 유지됩니다.

모든 계정은 **개인** 워크스페이스로 시작합니다. 한 사용자는 최대 10개의 워크스페이스에 속할 수 있고, 각 워크스페이스는 대기 중인 초대를 포함해 최대 10명의 멤버를 둘 수 있습니다.

### 워크스페이스 전환 또는 만들기

1. 상단 바에서 **워크스페이스** 메뉴를 엽니다.
2. 다른 워크스페이스를 선택하거나 **워크스페이스 만들기**를 클릭합니다.
3. 새 워크스페이스를 만들 때 이름(1~64자)을 입력하고 **워크스페이스 만들기**를 선택합니다.

**예상 결과:** 새 워크스페이스는 독립된 서비스, 정책, API 키, 일일 할당량을 가진 빈 상태로 생성되며 사용자가 **소유자**가 됩니다. URL은 `/w/<workspaceId>/service`로 바뀝니다. 워크스페이스를 전환하면 화면에 표시 중이던 일회성 비밀 값이 지워집니다.

### 워크스페이스 멤버 및 역할 관리

왼쪽 사이드바에서 **워크스페이스 설정 → 멤버**를 엽니다.

[![워크스페이스 멤버 페이지(소유자·관리자 목록, 멤버 초대 양식, 대기 중인 초대, 워크스페이스 나가기 카드)](/img/cloud/console/ko/02-workspace-members-page.png)](https://engine.speedle.io/img/cloud/console/ko/02-workspace-members-page.png)

워크스페이스 **멤버** 페이지 — 멤버 역할, 초대 양식, 대기 중인 초대 및 **워크스페이스 나가기**(데모 데이터, 한국어 UI).

| 역할 | 수행 가능한 작업 |
| --- | --- |
| **소유자** | 관리자의 모든 작업과 더불어 멤버 초대, 대기 중인 초대 취소, 역할 변경, 멤버 제거를 수행할 수 있습니다. |
| **관리자** | 서비스, 정책, 가져오기/내보내기, 함수, 플레이그라운드, API 키, ADS 플리트를 관리하고, 멤버 목록과 워크스페이스 감사 로그를 조회하며 워크스페이스에서 나갈 수 있습니다. |

**멤버 초대(소유자 전용):**

1. **멤버 초대** 섹션에서 **이메일 주소**를 입력하고 역할(**관리자** 또는 **소유자**)을 선택합니다.
2. **초대 보내기**를 선택합니다.

**예상 결과:** 7일간 유효한 일회용 초대 링크가 포함된 이메일이 발송되고 **대기 중인 초대**에 추가됩니다(10명 한도에 포함되며 초대자당 UTC 일 기준 최대 20건 발송 가능). 소유자에게는 전체 이메일이, 관리자에게는 마스킹된 이메일이 표시됩니다. 대기 중인 초대를 취소하려면 해당 항목의 **취소**를 선택합니다.

초대받은 사람은 이메일의 링크를 열고 해당 이메일이 인증된 GitHub 또는 Google 계정으로 로그인한 뒤 워크스페이스에 참여합니다.

**역할 변경, 멤버 제거 또는 워크스페이스 나가기:**

- **역할 변경(소유자 전용):** 멤버 옆의 역할 선택기에서 관리자를 소유자로 승격하거나 소유자를 관리자로 변경합니다.
- **멤버 제거(소유자 전용):** **제거**를 선택하고 경고를 확인한 뒤 확정합니다. 해당 멤버의 콘솔 접근은 다음 요청부터 종료됩니다.
- **워크스페이스 나가기:** **워크스페이스 나가기**를 선택하고 확인합니다.

> **멤버가 나가거나 제거되어도 해당 멤버가 생성한 API 키는 계속 유효합니다.** API 키는 생성자 개인이 아니라 워크스페이스에 속합니다. 멤버를 제거하면 콘솔이 그 멤버가 만든 활성 API 키 목록(이름, ID, 만료 시각, 비밀 값 제외)을 표시합니다. **API 키** 페이지에서 검토한 뒤 필요하면 취소하거나 교체하세요.

**복구 방법:**

- **본인 재인증 필요(`reauth_required`):** 역할 변경, 멤버 제거, 워크스페이스 나가기는 최근 10분 이내의 로그인 인증이 필요합니다. 연결된 공급자로 인증한 뒤 작업을 다시 실행하세요.
- **마지막 소유자(`last_owner`):** 워크스페이스에는 최소 1명의 소유자가 있어야 합니다. 자신을 강등하거나 나가기 전에 다른 멤버를 **소유자**로 지정하세요.
- **초대 이메일 불일치 또는 만료:** 초대된 이메일이 인증된 계정으로 로그인하도록 안내하거나(GitHub의 모든 인증 이메일 허용), 7일 만료 또는 취소된 경우 새 초대를 보내세요.

## 서비스 및 정책 관리

아래 예제는 역할 할당 1개와 인가 정책 1개를 가진 `books` 서비스를 사용합니다.

### 서비스 생성

1. 왼쪽 사이드바에서 **서비스 및 정책**을 엽니다.
2. 워크스페이스에 아직 서비스가 없다면 서비스 이름에 `books`를 입력하고 **서비스 생성**을 선택합니다. 이미 서비스가 있다면 **현재 서비스** 선택기에서 **다른 서비스 추가**를 선택해 `books`를 생성합니다.

서비스 이름은 1~64자의 영문자, 숫자, 점, 밑줄, 하이픈으로 구성하며 영문자 또는 숫자로 시작해야 합니다. `global`은 **전역 역할** 전용 예약 이름입니다. 애플리케이션은 인가 요청의 `serviceName`에 이 이름을 전달합니다.

### 인가 정책과 역할 정책 생성

1. `books`를 선택한 상태에서 **정책** 탭을 열고 **정책 생성**을 선택합니다.
2. 필요하면 **정책 이름**(최대 128 Unicode 문자, 예: `reader-role`)을 입력합니다. 비워 두면 이름이 자동으로 생성됩니다.
3. **SPDL 소스**에 단일 SPDL 문(UTF-8 기준 최대 1,024바이트)을 입력합니다.

```text
grant user alice from corp Reader
```

4. 입력을 잠시 멈추면 편집기가 자동으로 실시간 구문 검증을 실행하여 감지된 정책 유형(역할 정책 또는 인가 정책)과 구문 오류 또는 검토 경고를 표시합니다.
5. **정책 저장**을 선택합니다.
6. 같은 방식으로 역할에 권한을 부여하는 인가 정책(예: `read-books`)을 생성합니다.

```text
grant role Reader get /books
```

**예상 결과:** 두 정책이 `books` 정책 테이블에 표시됩니다. 저장된 정책은 **플레이그라운드**에 즉시 반영되며, 호스팅 인가 API에는 약 60초 내에 전파됩니다.

[![read-books 정책 생성 편집기(자동 실시간 SPDL 유효성 표시 및 정책 저장 버튼)](/img/cloud/console/ko/04-policy-editor-live-validation.png)](https://engine.speedle.io/img/cloud/console/ko/04-policy-editor-live-validation.png)

`read-books` 저장 전 자동 실시간 SPDL 검증 결과를 표시하는 정책 편집기(데모 데이터, 한국어 UI).

[![books 서비스의 서비스 및 정책 테이블(reader-role, read-books 및 서비스 탭)](/img/cloud/console/ko/03-service-policies-list.png)](https://engine.speedle.io/img/cloud/console/ko/03-service-policies-list.png)

`books` 서비스의 **서비스 및 정책** 목록(`reader-role`, `read-books` 및 서비스 탭. 데모 데이터, 한국어 UI).

코드 편집기와 일반 텍스트 편집기를 전환할 수 있으며 효과, 주체, 작업, 리소스, 역할, 조건 여부로 정책을 검색·필터링하고 각 행에서 편집, 세부 정보, 테스트, 삭제를 실행할 수 있습니다.

### 여러 서비스에서 전역 역할 사용

같은 워크스페이스의 여러 서비스가 동일한 역할 할당을 공유한다면 **전역 역할**에 한 번만 정의하세요.

1. **현재 서비스** 선택기 상단에서 **전역 역할**을 선택합니다.
2. `grant user alice from corp BookAdmin` 같은 역할 정책을 생성합니다.
3. 해당 역할을 사용할 각 일반 서비스(예: `books`)로 전환하여 `BookAdmin`에 권한을 부여하는 인가 정책을 생성합니다.

**전역 역할**에는 역할 정책만 저장할 수 있으며 이름 변경이나 삭제가 불가능합니다. 일반 서비스가 해당 역할에 대한 인가 정책을 정의하기 전까지는 어떤 권한도 부여되지 않습니다. 자세한 내용은 [전역 역할](/ko/docs/cloud/global-roles/)을 참고하세요.

### 액세스 맵에서 관계 살펴보기

**서비스 및 정책**의 **액세스 맵** 탭에서 저장된 정책의 주체, 역할, 리소스 연결을 시각화할 수 있습니다. 그래프 필터링, 테이블 보기 전환, 특정 노드 집중 보기를 지원하며 선택한 경로를 **플레이그라운드**로 바로 보내 **진단**을 실행할 수 있습니다.

[![books 서비스의 액세스 맵 그래프(alice → Reader → /books)](/img/cloud/console/ko/05-access-map.png)](https://engine.speedle.io/img/cloud/console/ko/05-access-map.png)

저장된 정책에서 `alice` → `Reader` → `/books`를 시각화한 **액세스 맵**(데모 데이터, 한국어 UI).

### 정책 가져오기 및 내보내기

**서비스 및 정책**의 **가져오기 및 내보내기** 탭을 엽니다.

- **SPDL 다운로드** 또는 **JSON 다운로드:** 선택한 서비스의 저장된 정책을 내보냅니다. 다운로드한 파일은 안전하게 보관하고 베타 기간 동안 별도 백업을 유지하세요.
- **정책 가져오기:** Speedle Cloud JSON 내보내기 파일(콘솔은 로컬 미리보기용으로 최대 32 MiB까지 읽을 수 있음)을 선택하고 미리보기 개수를 확인한 뒤 **정책 가져오기 확인**을 선택합니다. Cloud로 전송되는 가져오기 요청은 5,100,000바이트를 넘을 수 없으며, 초과하면 `413 request_too_large`를 반환합니다([제한과 오류](/ko/docs/cloud/limits-and-errors/) 참고). 가져오기는 원자적으로 처리되며 기존 정책을 덮어쓰지 않습니다. 가져오는 모든 정책에 서버가 새 ID를 부여하므로 배치 내부나 기존 정책과 표시 이름이 중복되어도 허용됩니다. 유효하지 않은 정책이 있거나 워크스페이스 전체 200개 정책 한도를 초과하면 전체 배치가 거부됩니다.

가져오기 도중 네트워크가 끊기거나 결과를 확인할 수 없다면 페이지를 닫지 말고 **동일한 가져오기 재시도**를 사용하세요. 같은 멱등성 키를 재사용하므로 이미 확정된 정책이 중복 삽입되지 않습니다. 반면 완료된 가져오기를 새 멱등성 키로 다시 실행하면 중복 정책이 생성되고 정책 한도를 소비합니다.

### 서비스 이름 변경 및 삭제

서비스 헤더 옆의 **서비스 작업** 메뉴를 사용합니다.

- **이름 변경…:** 서비스 이름을 변경합니다. 정책 ID, API 키, ADS 인스턴스 ID는 유지되지만 호출 애플리케이션은 `serviceName`을 새 이름으로 수정해야 하며 전파는 즉시 이루어지지 않습니다.
- **서비스 삭제…:** 서비스와 모든 정책을 영구 삭제하고 연결된 ADS 인스턴스에서 제거합니다. 서비스 이름을 입력해 확인합니다. 최근 10분 이내의 재인증이 필요하며, 안내 시 연결된 공급자로 인증한 뒤 삭제를 다시 확정합니다. 워크스페이스 API 키와 ADS 인스턴스는 유지됩니다.

**복구 방법:**

- **편집으로 정책 유형 변경 불가:** 저장된 인가 정책을 역할 정책으로(또는 반대로) 바꿀 수 없습니다. 정책을 삭제하고 새로 만드세요.
- **오래된 정책 편집 충돌:** 편집 중 다른 세션이 정책을 수정하거나 삭제해도 초안은 유지됩니다. 워크스페이스를 새로고침해 최신 버전을 연 뒤 저장하세요.
- **리비전 한도 도달(`revision_exhausted`):** 정책을 내보내고 새 서비스를 생성해 가져온 뒤 호출자를 새 `serviceName`으로 전환하고 필요하면 기존 서비스를 삭제합니다. [제한과 오류](/ko/docs/cloud/limits-and-errors/#revision-exhausted)를 참고하세요.

## 플레이그라운드에서 판정 테스트

1. **서비스 및 정책**에서 `books`를 선택하고 **플레이그라운드** 탭을 엽니다.
2. **작업 유형**을 선택합니다.
   - **허용 여부:** 허용 또는 거부와 사유 코드를 반환합니다.
   - **진단:** 판정 결과와 함께 정책·역할·조건의 평가 추적을 보여줍니다.
   - **부여된 모든 역할:** 해당 서비스에서 주체에 부여된 모든 역할(전역 역할 포함)을 나열합니다.
   - **부여된 모든 권한:** 주체에 허용된 모든 리소스와 작업을 나열합니다.
3. 테스트 입력을 작성합니다.
   - **주체(JSON):** `[{"type":"user","name":"alice","idd":"corp"}]`
   - **리소스:** `/books`
   - **작업:** `get`
   - **속성(JSON):** `[]`
4. **테스트 실행**을 선택합니다.

**예상 결과:** **허용 여부**가 허용 판정과 전체 JSON 결과를 표시합니다. **작업**을 `delete`로 바꾸고 다시 실행하면 일치하는 정책이 없어 거부가 반환됩니다.

[![플레이그라운드에서 corp 도메인의 alice가 /books get 요청 시 허용 결과와 전체 JSON 표시](/img/cloud/console/ko/06-playground-is-allowed-and-diagnose.png)](https://engine.speedle.io/img/cloud/console/ko/06-playground-is-allowed-and-diagnose.png)

**플레이그라운드** **허용 여부** 테스트 결과(`alice`/`corp`, `/books`, `get` — 허용 판정과 전체 JSON. 데모 데이터, 한국어 UI).

정책 행의 테스트 버튼이나 **액세스 맵**에서 입력을 미리 채울 수 있으며, **테스트 실행**을 클릭하기 전까지는 API 호출이 차감되지 않습니다.

**참고 사항:**

- 플레이그라운드는 **저장된** 정책을 즉시 평가하며 저장되지 않은 초안은 제외합니다.
- 실행할 때마다 워크스페이스 일일 할당량에서 1회가 차감되며 정책은 변경되지 않습니다.
- **전역 역할** 서비스 자체를 대상으로 한 판정은 항상 거부됩니다. 일반 서비스의 플레이그라운드에서 테스트하세요.
- 플레이그라운드 통과가 호스팅 [인가 API](/ko/docs/cloud/authorization-api/)의 스냅샷 전파 완료를 뜻하지는 않습니다(약 60초 소요).

## 워크스페이스 API 키 관리

API 키는 서버 애플리케이션과 자체 호스팅 Speedle Cloud ADS 인스턴스가 활성 워크스페이스에 접근할 때 사용합니다. 키 관리는 항상 로그인된 콘솔 세션이 필요합니다.

### API 키 생성

1. 왼쪽 사이드바에서 **API 키**를 엽니다.
2. **API 키 생성**을 선택합니다.
3. 용도를 알아볼 수 있는 **API 키 이름**(1~128자, 예: `books-app`)을 입력합니다. 이름에 비밀 값을 넣지 마세요.
4. **범위**(생성 시 고정)를 선택합니다.
   - **인가 확인 전용 (ADS)**(`ads`, 기본값): `/authz-check/v1/*`만 호출합니다.
   - **정책 관리: 읽기**(`pms:read`): 워크스페이스의 서비스와 정책을 읽습니다.
   - **정책 관리: 쓰기**(`pms:write`): 워크스페이스의 서비스와 정책을 읽고 생성하고 삭제합니다.
   - **ADS 동기화**(`pms:read+ads`): Speedle Cloud ADS(`speedle-cloud`) 정책 스냅샷 동기화, 정책 읽기, 인가 확인에 사용하며 쓰기는 불가합니다.
5. **유효 기간**(1주, 1개월, 3개월[기본값], 6개월, 1년)을 선택하고 **예상 만료 시간 (UTC)**을 확인합니다. 무기한 키는 지원하지 않습니다.
6. **API 키 생성**을 선택합니다. 최근 10분 이내의 공급자 인증이 필요하며, 안내 시 재인증 후 다시 제출합니다.
7. 일회성 비밀 값을 즉시 복사해 서버 비밀 저장소(예: `SPEEDLE_API_KEY`)에 저장한 뒤 표시를 닫습니다.

**예상 결과:** 새 키가 **활성 API 키** 목록에 ID, 범위, 생성 시각, 대략적 최근 사용 시각, 만료 시각(UTC)과 함께 표시됩니다. 비밀 값은 다시 표시되지 않으며 메타데이터로 복구할 수 없습니다.

[![API 키 페이지(API 키 생성 양식과 활성 키 메타데이터 목록, 비밀 값 미표시)](/img/cloud/console/ko/07-api-keys-list-and-create-form.png)](https://engine.speedle.io/img/cloud/console/ko/07-api-keys-list-and-create-form.png)

**API 키** 페이지 — **API 키 생성** 양식과 활성 키 메타데이터 목록(데모 데이터, 한국어 UI, 비밀 값 미표시).

### API 키 교체 및 취소

각 워크스페이스는 모든 범위를 합쳐 최대 **10개의 활성 API 키**를 보유할 수 있습니다. 7일 이내에 만료되는 키는 만료 임박으로 표시되며 만료된 키는 **만료된 API 키**로 이동합니다.

무중단 교체 절차:

1. 필요한 범위와 유효 기간으로 새 키를 생성합니다.
2. 애플리케이션 또는 ADS 설정을 새 키로 전환합니다.
3. **API 키** 페이지에서 이전 키의 **API 키 취소**를 선택하고 이름과 ID를 확인한 뒤 확정합니다.

**복구 방법:**

- **전파 지연:** 캐시된 검증 결과는 취소 후 최대 60초까지 유지될 수 있으므로 전 세계에 즉시 반영되지 않습니다.
- **한도 초과(`quota_exceeded`):** 사용하지 않는 키를 취소하거나 만료를 기다려 슬롯을 확보하세요. 취소·만료된 키는 이력에 남지만 10개 한도에 포함되지 않습니다.
- **결과 불확실:** 네트워크 오류로 생성이나 취소가 중단되면 목록을 새로고침해 활성/이력 그룹을 먼저 확인하세요. 같은 이름만으로 잃어버린 비밀 값을 추정하지 마세요.

자세한 내용은 [API 키](/ko/docs/cloud/tokens/) 문서를 참고하세요.

## 사용량 및 할당량 확인

공개 베타에서는 리소스 상한과 일일 호출 한도가 워크스페이스 단위로 적용됩니다.

- **서비스:** 워크스페이스당 100개(**전역 역할** 포함).
- **정책:** 워크스페이스 전체 서비스 합산 인가·역할 정책 200개(단일 SPDL 문 최대 1,024바이트 UTF-8).
- **활성 API 키:** 워크스페이스당 전체 범위 합산 10개.
- **일일 API 호출:** 워크스페이스당 UTC 일 기준 10,000회(`00:00 UTC` 초기화). 정책 관리 읽기/쓰기, 실시간 검증, 플레이그라운드, 가져오기/내보내기, 인가 확인이 이 한도를 공유합니다.

콘솔에서 사용량 확인 위치:

- **계정 → 계정 개요(`/account`):** 개인 워크스페이스의 **일일 할당량** 카드, 진행 막대, 다음 UTC 초기화 시각을 표시합니다.
- **서비스 및 정책:** 활성 워크스페이스의 서비스·정책 수와 작업 후 남은 대략적 일일 호출 수를 표시합니다.

[![계정 개요 페이지의 프로필과 일일 할당량 카드 및 UTC 초기화 시각](/img/cloud/console/ko/10b-account-overview-quota.png)](https://engine.speedle.io/img/cloud/console/ko/10b-account-overview-quota.png)

**계정 개요** — 프로필과 개인 워크스페이스 **일일 할당량** 표시기(데모 데이터, 한국어 UI).

일일 한도에 도달하면(`429 daily_quota_exceeded`) `00:00 UTC` 초기화를 기다려야 합니다. 같은 워크스페이스에서 API 키를 바꿔도 한도는 늘어나지 않습니다. 자세한 내용은 [제한과 오류](/ko/docs/cloud/limits-and-errors/)를 참고하세요.

## 사용자 정의 함수 (서비스별)

> 환경에서 사용자 정의 함수가 활성화되어 있으면 일반 서비스의 **액세스 맵**과 **플레이그라운드** 사이에 **함수** 탭이 표시됩니다.

사용자 정의 함수를 사용하면 SPDL 조건이 평가 중 외부 HTTPS 엔드포인트를 호출할 수 있습니다. 일반 서비스당 최대 **20개의 함수**를 등록할 수 있습니다.

### 함수 등록 및 관리

1. 일반 서비스를 선택하고 **함수** 탭을 엽니다.
2. **함수 등록**을 선택합니다.
3. 다음 항목을 설정합니다.
   - **이름:** 1~64자 SPDL 식별자(예약어 불가).
   - **엔드포인트 URL:** 조건 인수를 받는 HTTPS 엔드포인트(UTF-8 최대 2,048바이트, 일반 HTTP 불가). 콘솔 자체는 엔드포인트를 호출하지 않습니다. URL 규칙은 **호출 위치**에 따라 달라집니다.
     - **호스팅 및 ADS:** 기본 포트 `443`의 `https://`와 공개 비예약 DNS 호스트 이름(2개 이상 레이블)이 필요하며, IP 리터럴, 443 외 포트, `localhost`, `*.local`, `*.internal`, `*.home.arpa`, `.test`, `.example`, `.invalid`, `.alt`, `.onion` 같은 내부·예약 호스트는 거부됩니다.
     - **ADS 전용:** `https://`가 필요하지만 임의 포트와 IP 리터럴, 사설·내부 호스트 이름을 허용합니다(예: `https://10.20.30.40:8443/func/check`).
     - 두 모드 모두 사용자 정보(`user@host`), 프래그먼트(`#...`), 공백, 제어 문자, 백슬래시를 거부합니다.
   - **호출 위치:** **호스팅 및 ADS**(Cloud 호스팅 평가, 플레이그라운드, 자체 호스팅 ADS 모두 호출 가능) 또는 **ADS 전용**(자체 호스팅 ADS에서만 호출 가능하며 호스팅 평가나 플레이그라운드가 도달하면 평가 실패).
   - **선언된 유형(선택):** 최대 16개의 매개변수 유형과 결과 유형을 선언할 수 있습니다. 선언하지 않으면 인수 유형을 검사하지 않으며, 선언된 유형이 일치하지 않으면 평가가 실패합니다.
   - **결과 캐시(선택):** 평가기 로컬 캐시 TTL(1~86,400초, 실패는 캐시되지 않음).
   - **호스팅 시간 제한(ms):** 100~2,000 ms(기본 1,000 ms), 호스팅 호출에만 적용됩니다.
   - **호스팅 요청 서명(선택):** Cloud 호스팅 요청에만 HMAC 서명을 활성화합니다. **호스팅 및 ADS**를 선택해도 자체 호스팅 ADS는 항상 서명 없는 요청을 보냅니다.
4. **함수 저장**을 선택합니다. 서명을 활성화한 경우 대화 상자를 닫기 전에 일회성 서명 비밀 키를 복사해 보관하세요.

함수 목록에서 함수 편집, **서명 비밀 키 교체**(이전 키는 즉시 무효화되며 최근 재인증이 필요할 수 있음), **함수 삭제**를 수행할 수 있습니다.

[![books 서비스의 함수 탭(호스팅 및 ADS와 ADS 전용 예제 함수 목록)](/img/cloud/console/ko/08-functions-tab.png)](https://engine.speedle.io/img/cloud/console/ko/08-functions-tab.png)

`books` 서비스의 **함수** 탭 — **호스팅 및 ADS** 및 **ADS 전용** 예제 함수(데모 데이터, 한국어 UI, 실제 엔드포인트 호출 없음).

**중요 규칙 및 복구:**

- **`function_url_rejected`:** URL이 `https://`인지, 사용자 정보·프래그먼트·공백·백슬래시가 없는지 확인하세요. IP 리터럴, 내부 호스트, 비-443 포트는 **ADS 전용**을 선택하고, **호스팅 및 ADS**에는 포트 `443`의 공개 DNS 호스트 이름을 사용하세요.
- 함수를 호출하는 정책을 저장하거나 가져오기 전에 대상 서비스에 함수를 먼저 등록해야 합니다. 정책 내보내기에는 함수 정의가 포함되지 않습니다.
- 정책이 참조 중인 함수는 삭제할 수 없으므로 먼저 참조 정책을 수정하거나 삭제하세요.

## ADS 플리트 모니터링 및 제어

왼쪽 사이드바에서 **ADS 플리트**를 열어 활성 워크스페이스에서 정책을 동기화하는 자체 호스팅 Speedle Cloud ADS(`speedle-cloud`) 인스턴스를 관리합니다. Cloud는 사용자 네트워크로 먼저 연결하지 않으며, 모든 명령은 각 인스턴스가 연 채널을 통해 전달됩니다.

### 첫 번째 ADS 인스턴스 연결

수동 등록 절차는 없습니다. 플리트가 비어 있으면 **ADS 플리트** 페이지에 3단계 온보딩 안내와 복사 가능한 설정 스니펫이 표시됩니다.

1. **API 키** 페이지에서 **ADS 동기화**(`pms:read+ads`) 범위의 API 키를 생성합니다.
2. 키를 ADS 설정 파일(권한 `0600`)에 넣고 재시작 시 인스턴스 ID를 유지하도록 영구 볼륨의 `CacheDir`를 지정합니다.
3. 애플리케이션 리스너 TLS 설정과 함께 `speedle-cloud`를 시작하면 첫 연결 시 **ADS 플리트**에 자동으로 나타납니다.

워크스페이스당 최대 **10개의 온라인 ADS 인스턴스**를 지원하며 최대 **100개의 인스턴스 기록**을 보관합니다(7일간 오프라인인 인스턴스는 자동 삭제).

### 인스턴스 점검 및 배포 작업 실행

**서비스 필터**로 특정 서비스를 동기화하는 인스턴스만 보거나 **플리트 새로고침**으로 즉시 갱신할 수 있습니다(페이지가 보이는 동안 5분마다 자동 새로고침).

[![ADS 플리트 페이지에서 books를 동기화하는 온라인 데모 ADS 인스턴스 표시](/img/cloud/console/ko/09-ads-fleet-view.png)](https://engine.speedle.io/img/cloud/console/ko/09-ads-fleet-view.png)

`books`를 동기화하는 데모 온라인 인스턴스를 표시한 **ADS 플리트** 화면(데모 데이터, 한국어 UI).

인스턴스 행의 **세부 정보**를 열면 실시간 상태, 마지막 하트비트(UTC), 채널 및 전송 방식(WebSocket 또는 롱 폴링), 리비전 지연과 **전역 역할**(항상 동기화)이 포함된 서비스 세트, 배포 체인, 이벤트 타임라인, 폴백 기록, 호스트 정보를 확인할 수 있습니다.

지원 작업(모두 확인 필요):

- **서비스 할당:** 향후 생성되는 서비스를 포함한 전체 서비스 또는 선택한 서비스만 동기화하도록 설정합니다. 재시작 없이 다음 하트비트에 반영됩니다.
- **스냅샷에서 재동기화:** 인스턴스의 로컬 복사본을 폐기하고 스냅샷을 다시 불러옵니다. **가용성 영향:** 새 스냅샷을 내려받아 검증할 때까지 해당 서비스의 로컬 인가 판정이 즉시 중단됩니다.
- **배포 일시 중지 / 배포 재개:** 로컬 동기화와 판정은 유지한 채 하위 ADS 인스턴스로의 정책 배포를 중지하거나 재개합니다.
- **이 ADS 중지:** 인스턴스가 모든 인가 요청을 거부하고 재시작할 때까지 재연결을 중지하도록 지시합니다.
- **이 인스턴스 삭제:** 인스턴스 기록과 이력을 삭제합니다(실행 중인 인스턴스는 중지하거나 API 키를 취소하지 않으면 다음 연결 시 다시 등록됩니다).

## 감사 로그 확인 및 계정 설정 관리

### 감사 로그

Speedle Cloud는 최신순으로 정렬되고 **180일간 보관**되며 페이지 이동을 지원하는 두 종류의 감사 로그를 제공합니다.

- **워크스페이스 감사 로그**(왼쪽 사이드바 → **감사 로그**): 활성 워크스페이스 내 관리 활동(서비스·정책 변경, API 키 생성/취소, ADS 작업, 워크스페이스 변경, 멤버·초대 변경)을 기록합니다. 소유자와 관리자 모두 열람할 수 있습니다.
- **개인 활동**(상단 바 **계정** 메뉴 → **계정 개요** → **개인 활동**, `/account/audit`): 로그인, 로그아웃, 모든 기기에서 로그아웃, 로그인 수단 연결/해제, 계정 생성/삭제 등 개인 계정 이벤트를 기록합니다.

[![워크스페이스 감사 로그 테이블(UTC 시각, 작업, 대상, 결과)](/img/cloud/console/ko/10a-workspace-audit-log.png)](https://engine.speedle.io/img/cloud/console/ko/10a-workspace-audit-log.png)

워크스페이스 **감사 로그** — 최근 관리 이벤트를 UTC 기준으로 표시(데모 데이터, 한국어 UI).

### 계정 설정

상단 바 **계정** 메뉴에서 **계정 설정**(`/account/settings`)을 엽니다.

- **연결된 로그인 수단:** 예비 로그인 수단을 위해 **GitHub**와 **Google**을 모두 연결해 두는 것이 좋습니다. 최소 하나의 로그인 수단을 유지해야 하며 연결 해제에는 최근 10분 이내의 인증이 필요합니다.
- **로그아웃 / 모든 기기에서 로그아웃:** 상단 바 **계정** 메뉴에서 현재 세션 또는 모든 활성 세션을 종료합니다.
- **계정 삭제:** 개인 계정, 연결된 로그인 수단, 본인만 속한 워크스페이스와 모든 세션을 영구 삭제합니다. **계정 삭제**를 선택하고 안내 시 재인증한 뒤 `DELETE`를 입력해 확정합니다. 보관할 정책은 먼저 내보내세요.

[![계정 설정 페이지의 연결된 로그인 수단(GitHub·Google) 및 계정 삭제 카드](/img/cloud/console/ko/10c-account-settings.png)](https://engine.speedle.io/img/cloud/console/ko/10c-account-settings.png)

**계정 설정** — **연결된 로그인 수단**과 **계정 삭제** 카드(데모 데이터, 한국어 UI).

**계정 삭제가 차단될 때 복구:** 다른 멤버가 남아 있는 워크스페이스의 유일한 **소유자**인 경우 계정 삭제가 차단됩니다(`last_owner`). 해당 워크스페이스의 **멤버** 페이지에서 다른 멤버를 **소유자**로 승격한 뒤 계정을 삭제하세요.
