**Speedle Cloud はパブリックベータを提供中です。** 無料パブリックベータは評価・学習用で SLA はなく、本番利用は推奨しません。機能と制限は変更される場合があります。

このマニュアルでは、[cloud.speedle.io](https://cloud.speedle.io/ja/) の **Speedle Cloud Console（SCC）** での日常操作を説明します。サーバーから素早く API を呼び出す手順は[クイックスタート](/ja/docs/cloud/getting-started/)を、リクエスト仕様・エラーコード・利用上限の詳細は[認可 API](/ja/docs/cloud/authorization-api/)、[API リファレンス](/ja/docs/cloud/api-reference/)、[制限とエラー](/ja/docs/cloud/limits-and-errors/)を参照してください。

## サインインとコンソール構成

### 前提条件

- JavaScript と Cookie を有効にしたブラウザー。
- メールアドレスを確認済みの GitHub または Google アカウント。

### サインインまたはアカウント作成

1. [cloud.speedle.io](https://cloud.speedle.io/ja/) を開き、**使ってみる** を選択します（または `/login` を直接開きます）。
2. GitHub または Google でのサインインを選択し、プロバイダー側で認証を完了します。
3. 未使用の確認済みメールアドレスで初めてサインインする場合は、利用規約とプライバシーポリシーのリンクを確認し、**アカウントを作成** を確定します。

**期待される結果：** アクティブなワークスペースの **サービスとポリシー**（`/w/<workspaceId>/service`）が開きます。新規アカウントには、自分が **オーナー** となる **パーソナル** ワークスペースが用意されます。

**復旧手順：**

- **メールアドレスが使用中：** そのメールアドレスにすでに紐付いているプロバイダーでサインインし、**アカウント設定** から 2 つ目のプロバイダーを接続してください。
- **確認済みメールアドレスが必要：** GitHub または Google の設定でメールアドレスを確認してから再度サインインしてください。
- **新規登録が一時停止中：** ベータの新規アカウント上限に達しています。既存アカウントは引き続きサインインできます。
- **セッション期限切れ：** セッションは 7 日間無操作、または作成から 30 日間のいずれか早い方で失効します。再度サインインしてください。

### コンソールのナビゲーション

サインイン後のコンソールには 2 つのナビゲーション領域があります。

- **トップバー：**
  - **Speedle | Cloud** ロゴ：アクティブなワークスペースの **サービスとポリシー** に戻ります。
  - **ワークスペース** 切替メニュー：現在のワークスペース名とロール（**オーナー** または **管理者**）を表示し、ワークスペースの切り替えと **ワークスペースを作成** を提供します。
  - ヘルプリンク、**言語** 切替、**アカウント** メニュー（メールアドレス、**アカウント概要**、**アカウント設定**、**サインアウト**、**すべてのデバイスからサインアウト**）。
- **左サイドバー：**
  - **コンソール：** **サービスとポリシー**、**API キー**、**ADS フリート**、**監査ログ** — いずれもアクティブなワークスペースに紐付きます。
  - **ワークスペース設定：** **メンバー** — ワークスペースのメンバーシップを表示・管理します。
  - **Cloud ドキュメント：** このドキュメントを開きます。

## 個人アカウントとワークスペース

Speedle Cloud は**個人アカウント**と**ワークスペース**を分離しています。

- **個人アカウント**は、確認済みメールアドレス、接続済みのサインインプロバイダー（GitHub / Google）、ブラウザーセッション、**個人のアクティビティ**（`/account/audit`）を保持します。
- **ワークスペース**は、サービス、認可・ロールポリシー（**グローバルロール**を含む）、カスタム関数、API キー、ADS フリートインスタンス、ワークスペースの **監査ログ**、1 日の API 割り当てを分離管理するコンテナです。

すべてのアカウントは **パーソナル** ワークスペースから始まります。1 人のユーザーは最大 10 個のワークスペースに所属でき、各ワークスペースには保留中の招待を含めて最大 10 名のメンバーを登録できます。

### ワークスペースの切り替えと作成

1. トップバーの **ワークスペース** メニューを開きます。
2. 別のワークスペースを選択して切り替えるか、**ワークスペースを作成** を選びます。
3. 新規作成時はワークスペース名（1〜64 文字）を入力し、**ワークスペースを作成** を選択します。

**期待される結果：** 独自のサービス、ポリシー、API キー、日次割り当てを持つ空のワークスペースが作成され、自分が **オーナー** になります。URL は `/w/<workspaceId>/service` に切り替わります。ワークスペースを切り替えると、画面に表示中の一度限りのシークレットは消去されます。

### ワークスペースのメンバーとロール管理

左サイドバーから **ワークスペース設定 → メンバー** を開きます。

| ロール | 実行できる操作 |
| --- | --- |
| **オーナー** | 管理者の全操作に加え、メンバー招待、保留中の招待の取り消し、ロール変更、メンバー削除を行えます。 |
| **管理者** | サービス、ポリシー、インポート/エクスポート、関数、プレイグラウンド、API キー、ADS フリートを管理し、メンバー一覧とワークスペース監査ログを閲覧し、ワークスペースを退出できます。 |

**メンバーを招待する（オーナーのみ）：**

1. **メンバーを招待** セクションで **メールアドレス** を入力し、ロール（**管理者** または **オーナー**）を選択します。
2. **招待を送信** を選択します。

**期待される結果：** 7 日間有効な使い捨て招待リンクを含むメールが送信され、**保留中の招待** に追加されます（10 名上限に算入、1 人の招待者あたり 1 UTC 日につき最大 20 通）。オーナーには完全なメールアドレスが、管理者にはマスクされたアドレスが表示されます。取り消す場合は該当行の **取り消す** を選択します。

招待を受けた人はメールのリンクを開き、そのメールアドレスが確認済みの GitHub または Google アカウントでサインインして参加します。

**ロール変更・メンバー削除・退出：**

- **ロール変更（オーナーのみ）：** メンバー横のロール選択で管理者をオーナーに昇格、またはオーナーを管理者に降格します。
- **メンバー削除（オーナーのみ）：** **削除** を選択し、警告を確認して確定します。対象メンバーのコンソールアクセスは次のリクエストから停止します。
- **ワークスペースを退出：** **ワークスペースを退出** を選択して確定します。

> **メンバーが退出または削除されても、そのメンバーが作成した API キーは有効なまま残ります。** API キーは作成者個人ではなくワークスペースに属します。メンバー削除後、コンソールにはそのメンバーが作成した有効な API キー一覧（名前・ID・有効期限、シークレットは非表示）が表示されます。**API キー** ページで確認し、必要に応じて取り消しまたはローテーションしてください。

**復旧手順：**

- **最近の再認証が必要（`reauth_required`）：** ロール変更・メンバー削除・退出には過去 10 分以内のサインインが必要です。接続済みプロバイダーで再認証した後、操作を再実行してください。
- **最後のオーナー（`last_owner`）：** ワークスペースには最低 1 名のオーナーが必要です。自身の降格や退出の前に別のメンバーを **オーナー** に昇格してください。
- **招待メールの不一致またはリンク失効：** 招待先メールが確認済みのアカウントでサインインしてもらい（GitHub の確認済みメールアドレスであればいずれでも可）、7 日間の期限切れや取り消し済みの場合は再招待してください。

## サービスとポリシーの管理

以下では、ロール割り当て 1 件と認可ポリシー 1 件を持つ `books` サービスを例に説明します。

### サービスを作成

1. 左サイドバーから **サービスとポリシー** を開きます。
2. ワークスペースにサービスがまだない場合は `books` を入力して **サービスを作成** を選択します。既存サービスがある場合は **現在のサービス** セレクターを開き、**別のサービスを追加** から `books` を作成します。

サービス名は 1〜64 文字（英数字、ドット、アンダースコア、ハイフン、先頭は英数字）です。`global` は **グローバルロール** 用に予約されています。アプリケーションは認可リクエストの `serviceName` にこの名前を指定します。

### 認可ポリシーとロールポリシーを作成

1. `books` を選択した状態で **ポリシー** タブを開き、**ポリシーを作成** を選択します。
2. 必要に応じて **ポリシー名**（最大 128 Unicode 文字、例：`reader-role`）を入力します。空のままにすると自動的に名前が生成されます。
3. **SPDL ソース** に 1 つの SPDL ステートメント（UTF-8 で最大 1,024 バイト）を入力します。

```text
grant user alice from corp Reader
```

4. 入力を一時停止するとリアルタイム検証が自動実行され、検出されたポリシー種別（ロールポリシーまたは認可ポリシー）と構文エラー・レビュー警告が表示されます。
5. **ポリシーを保存** を選択します。
6. 同様に、ロールに権限を付与する認可ポリシー（例：`read-books`）を作成します。

```text
grant role Reader get /books
```

**期待される結果：** 両方のポリシーが `books` のポリシー一覧に表示されます。保存されたポリシーは **プレイグラウンド** で即座に利用でき、ホスト型認可 API へは約 60 秒で反映されます。

コードエディターとプレーンテキストエディターの切り替え、効果・プリンシパル・アクション・リソース・ロール・条件の有無による検索・フィルター、各行からの編集・詳細・テスト・削除が可能です。

### 複数サービスでグローバルロールを使用

同じワークスペース内の複数サービスでロール割り当てを共有する場合は、**グローバルロール** に一度だけ定義します。

1. **現在のサービス** セレクターの先頭から **グローバルロール** を選択します。
2. `grant user alice from corp BookAdmin` のようなロールポリシーを作成します。
3. そのロールを使う各通常サービス（例：`books`）へ切り替え、`BookAdmin` に権限を付与する認可ポリシーを作成します。

**グローバルロール** はロールポリシーのみ受け付け、名前変更や削除はできません。通常サービス側に認可ポリシーがない限り権限は付与されません。詳細は[グローバルロール](/ja/docs/cloud/global-roles/)を参照してください。

### アクセスマップで関係を確認

**サービスとポリシー** 内の **アクセスマップ** タブでは、保存済みポリシーのプリンシパル・ロール・リソースの関係を可視化できます。フィルター、テーブル表示切替、ノードフォーカスに対応し、選択パスを **プレイグラウンド** に送って **診断** を実行できます。

### ポリシーのインポートとエクスポート

**サービスとポリシー** 内の **インポートとエクスポート** タブを開きます。

- **SPDL をダウンロード** / **JSON をダウンロード：** 選択中サービスの保存済みポリシーをエクスポートします。ダウンロードしたファイルは安全に保管し、ベータ期間中は自身でバックアップを維持してください。
- **ポリシーをインポート：** Speedle Cloud の JSON エクスポートファイル（最大 32 MiB）を選択し、プレビュー件数を確認して **ポリシーのインポートを確認** を選択します。インポートはアトミックに実行され、既存ポリシーは上書きされません。インポートされる各ポリシーにはサーバー側で新しい ID が発行されるため、バッチ内や既存ポリシーと表示名が重複していても許可されます。無効なポリシーが含まれる場合、またはワークスペース全体の 200 ポリシー上限を超える場合のみバッチ全体が拒否されます。

インポート中に通信が途切れて結果が不明な場合は、ページを閉じずに **同じインポートを再試行** を使ってください。同じ冪等性キーを再利用するため、確定済みポリシーが二重登録されません。一方、完了済みインポートを新しい冪等性キーで再実行すると重複ポリシーが作成され、ポリシー枠を消費します。

### サービス名の変更と削除

サービス見出し横の **サービスの操作** メニューを使用します。

- **名前を変更…：** サービス名を変更します。ポリシー ID、API キー、ADS インスタンス ID は維持されますが、呼び出し側アプリケーションの `serviceName` を更新する必要があり、反映は即時ではありません。
- **サービスを削除…：** サービスとすべてのポリシーを完全に削除し、関連する ADS インスタンスから除外します。確認のためサービス名を入力します。過去 10 分以内の認証が必要で、求められた場合は再認証後に再度確定します。ワークスペースの API キーと ADS インスタンスは残ります。

**復旧手順：**

- **編集でポリシー種別は変更不可：** 保存済みの認可ポリシーをロールポリシー（またはその逆）に変更できません。削除して作り直してください。
- **古いポリシーの競合：** 編集中に他セッションで変更・削除された場合でもドラフトは保持されます。ワークスペースを更新して最新版を開き直してから保存してください。
- **リビジョン上限到達（`revision_exhausted`）：** ポリシーをエクスポートし、新サービスへインポートして呼び出し元の `serviceName` を切り替えた後、必要に応じて旧サービスを削除します。[制限とエラー](/ja/docs/cloud/limits-and-errors/#revision-exhausted)を参照してください。

## プレイグラウンドでの判定テスト

1. **サービスとポリシー** で `books` を選択し、**プレイグラウンド** タブを開きます。
2. **操作タイプ** を選択します。
   - **許可確認：** 許可または拒否と理由コードを返します。
   - **診断：** 判定結果と、ポリシー・ロール・条件がどう寄与したかのトレースを表示します。
   - **付与されたすべてのロール：** このサービスで対象プリンシパルに付与されるすべてのロール（グローバルロール含む）を一覧表示します。
   - **付与されたすべての権限：** 付与されるすべてのリソースとアクションを一覧表示します。
3. テスト入力を記入します。
   - **プリンシパル (JSON)：** `[{"type":"user","name":"alice","idd":"corp"}]`
   - **リソース：** `/books`
   - **アクション：** `get`
   - **属性 (JSON)：** `[]`
4. **テストを実行** を選択します。

**期待される結果：** **許可確認** で許可判定と完全な JSON 結果が表示されます。**アクション** を `delete` に変えて再実行すると、一致するポリシーがないため拒否になります。

ポリシー一覧の各行や **アクセスマップ** から入力を事前入力でき、**テストを実行** を押すまで API 呼び出しは消費されません。

**注意点：**

- プレイグラウンドは**保存済み**のポリシーを即時に評価し、未保存ドラフトは対象外です。
- 1 回の実行でワークスペースの日次割り当てを 1 回消費し、ポリシーは変更しません。
- **グローバルロール** 自体への判定は常に拒否されます。通常サービスのプレイグラウンドでテストしてください。
- プレイグラウンド成功は、公開スナップショットが全ホストノードへ伝播完了したことを保証しません（ホスト型[認可 API](/ja/docs/cloud/authorization-api/)は約 60 秒見込んでください）。

## ワークスペース API キーの管理

API キーはサーバー側アプリケーションやセルフホスト型 Speedle Cloud ADS インスタンスをアクティブなワークスペースへ認証します。キーの管理には常にサインイン済みコンソールセッションが必要です。

### API キーを作成

1. 左サイドバーから **API キー** を開きます。
2. **API キーを作成** を選択します。
3. 用途が分かる **API キー名**（1〜128 文字、例：`books-app`）を入力します。名前にシークレットを入れないでください。
4. **スコープ**（作成時に固定）を選択します。
   - **認可チェックのみ (ADS)**（`ads`、既定）：`/authz-check/v1/*` のみ呼び出します。
   - **ポリシー管理: 読み取り**（`pms:read`）：ワークスペースのサービスとポリシーを読み取ります。
   - **ポリシー管理: 書き込み**（`pms:write`）：ワークスペースのサービスとポリシーを読み取り・作成・削除します。
   - **ADS 同期**（`pms:read+ads`）：Speedle Cloud ADS（`speedle-cloud`）のポリシー同期、読み取り、認可チェック用。書き込み不可。
5. **有効期間**（1 週間、1 か月、3 か月［既定］、6 か月、1 年）を選び、**有効期限のプレビュー (UTC)** を確認します。無期限キーは作成できません。
6. **API キーを作成** を選択します。作成には過去 10 分以内の認証が必要で、求められた場合は再認証後に再度フォームを送信します。
7. 一度だけ表示されるシークレットを直ちにコピーし、サーバーのシークレット管理（例：`SPEEDLE_API_KEY`）へ保存してから表示を閉じます。

**期待される結果：** 新しいキーが **有効な API キー** に ID、スコープ、作成日時、おおよその最終使用日時、有効期限（UTC）とともに表示されます。シークレットは二度と表示されず、メタデータから復元できません。

### API キーのローテーションと取り消し

各ワークスペースでは全スコープ合計で最大 **10 個の有効な API キー** を保持できます。7 日以内に失効するキーには期限間近の表示が付き、失効したキーは **期限切れの API キー** に移動します。

無停止ローテーション手順：

1. 必要なスコープと有効期間で新しいキーを作成します。
2. アプリケーションまたは ADS の設定を新しいキーに切り替えます。
3. **API キー** ページで旧キーの **API キーを取り消す** を選び、名前と ID を確認して確定します。

**復旧手順：**

- **伝播遅延：** キャッシュされた検証結果は取り消し後も最大 60 秒有効な場合があり、世界中で即時失効するわけではありません。
- **上限到達（`quota_exceeded`）：** 未使用キーを取り消すか失効を待って枠を空けてください。取り消し済み・期限切れのキーは履歴に残り、10 個の上限には数えません。
- **結果不明時：** 通信エラーで作成や取り消しが中断された場合は、一覧を更新して有効・履歴グループを確認してから再操作してください。同じ名前だけで失われたシークレットを推測しないでください。

契約の詳細は [API キー](/ja/docs/cloud/tokens/)を参照してください。

## 使用量と割り当ての確認

パブリックベータのリソース上限と日次 API 呼び出し枠はワークスペース単位です。

- **サービス：** ワークスペースあたり 100 件（**グローバルロール**を含む）。
- **ポリシー：** ワークスペース全体で認可・ロールポリシー合計 200 件（1 ステートメント最大 1,024 バイト UTF-8）。
- **有効な API キー：** ワークスペースあたり全スコープ合計 10 個。
- **1 日の API 呼び出し：** ワークスペースあたり 1 UTC 日 10,000 回（`00:00 UTC` リセット）。管理読み書き、リアルタイム検証、プレイグラウンド、インポート/エクスポート、認可チェックで共有します。

コンソールでの確認場所：

- **アカウント → アカウント概要（`/account`）：** パーソナルワークスペースの **1日の割り当て** カード、使用メーター、次回 UTC リセット時刻を表示します。
- **サービスとポリシー：** アクティブなワークスペースのサービス数・ポリシー数と、操作後の残り呼び出し回数目安を表示します。

日次枠に達した場合（`429 daily_quota_exceeded`）は `00:00 UTC` まで待機してください。同じワークスペース内で API キーを変えても枠は増えません。詳細は[制限とエラー](/ja/docs/cloud/limits-and-errors/)を参照してください。

## カスタム関数（サービス単位）

> ステージでカスタム関数が有効な場合、通常サービスの **アクセスマップ** と **プレイグラウンド** の間に **関数** タブが表示されます。

カスタム関数を使うと、SPDL 条件の評価中に外部 HTTPS エンドポイントを呼び出せます。通常サービスごとに最大 **20 個の関数** を登録できます。

### 関数の登録と管理

1. 通常サービスを選択し、**関数** タブを開きます。
2. **関数を登録** を選択します。
3. 各項目を設定します。
   - **名前：** 1〜64 文字の SPDL 識別子（予約語は不可）。
   - **エンドポイント URL：** 条件引数を受け取る HTTPS エンドポイント（UTF-8 最大 2,048 バイト、平文 HTTP 不可）。コンソール自体はエンドポイントを呼び出しません。URL 規則は **呼び出し先** に依存します。
     - **ホスト型と ADS：** 既定ポート `443` の `https://` と公開非予約 DNS ホスト名（2 ラベル以上）が必須で、IP リテラル、443 以外のポート、`localhost`、`*.local`、`*.internal`、`*.home.arpa`、`.test`、`.example`、`.invalid`、`.alt`、`.onion` などの内部・予約ホストは拒否されます。
     - **ADS のみ：** `https://` が必須ですが、任意のポート、IP リテラル、プライベート/内部ホスト名を許可します（例：`https://10.20.30.40:8443/func/check`）。
     - どちらのモードでもユーザー情報（`user@host`）、フラグメント（`#...`）、空白、制御文字、バックスラッシュは拒否されます。
   - **呼び出し先：** **ホスト型と ADS**（Cloud ホスト評価・プレイグラウンド・セルフホスト ADS から呼び出し可能）または **ADS のみ**（セルフホスト ADS 専用。ホスト評価やプレイグラウンドが到達すると評価失敗）。
   - **宣言された型（任意）：** 最大 16 個のパラメーター型と結果型を宣言できます。未宣言の場合は引数型を検証せず、宣言と不一致の場合は評価が失敗します。
   - **結果をキャッシュ（任意）：** 評価器ローカルのキャッシュ TTL（1〜86,400 秒。失敗はキャッシュされません）。
   - **ホスト型タイムアウト（ms）：** 100〜2,000 ms（既定 1,000 ms）、ホスト型呼び出しにのみ適用されます。
   - **ホスト型リクエストに署名（任意）：** Cloud ホスト型リクエストにのみ HMAC 署名を有効にします。**ホスト型と ADS** を選択しても、セルフホスト ADS は常に未署名リクエストを送信します。
4. **関数を保存** を選択します。署名を有効にした場合は、ダイアログを閉じる前に一度限りの署名シークレットをコピーして保管してください。

一覧から関数の編集、**署名シークレットを更新**（旧シークレットは即時失効、最近の再認証が必要な場合あり）、**関数を削除** を行えます。

**重要な規則と復旧：**

- **`function_url_rejected`：** URL が `https://` であり、ユーザー情報・フラグメント・空白・バックスラッシュを含まないことを確認してください。IP リテラル・内部ホスト・443 以外のポートには **ADS のみ** を選択し、**ホスト型と ADS** にはポート `443` の公開 DNS ホスト名を使用してください。
- 関数を呼び出すポリシーを保存またはインポートする**前**に、対象サービスへ関数を登録してください。ポリシーのエクスポートには関数定義は含まれません。
- ポリシーから参照されている関数は削除できません。先に参照元のポリシーを編集または削除してください。

## ADS フリートの監視と制御

左サイドバーの **ADS フリート** を開き、アクティブなワークスペースからポリシーを同期するセルフホスト型 Speedle Cloud ADS（`speedle-cloud`）インスタンスを監視します。Cloud から顧客ネットワークへ接続することはなく、コマンドは各インスタンスが開いたチャネル経由で届きます。

### 最初の ADS インスタンスを接続

手動登録は不要です。フリートが空のときは、**ADS フリート** ページに 3 ステップの接続手順とコピー可能な設定スニペットが表示されます。

1. **API キー** ページで **ADS 同期**（`pms:read+ads`）スコープのキーを作成します。
2. キーを ADS 設定ファイル（権限 `0600`）に記述し、再起動後も同一インスタンス ID を保つため永続ボリューム上の `CacheDir` を指定します。
3. アプリケーションリスナーの TLS 設定を指定して `speedle-cloud` を起動すると、初回接続時に **ADS フリート** に自動表示されます。

ワークスペースあたり最大 **10 台のオンライン ADS インスタンス** に対応し、最大 **100 件のインスタンス記録** を保持します（7 日間オフラインのインスタンスは自動削除されます）。

### インスタンスの詳細確認と配信操作

**サービスフィルター** で特定サービスを同期するインスタンスを絞り込むか、**フリートを更新** で即時更新できます（表示中は 5 分ごとに自動更新）。

各行の **詳細** を開くと、ライブ状態、最終ハートビート（UTC）、チャネルとトランスポート（WebSocket / ロングポーリング）、リビジョン遅延と **グローバルロール**（常に同期）を含むサービスセット、配信チェーン、イベントタイムライン、フォールバック履歴、ホスト情報を確認できます。

実行可能な操作（すべて確認あり）：

- **サービスを割り当て：** 将来作成されるサービスを含む全サービス、または選択したサービスのみを同期するよう指定します。再起動なしで次のハートビートに反映されます。
- **スナップショットから再同期：** インスタンスのローカルコピーを破棄してスナップショットを再読み込みします。**可用性への影響：** 新しいスナップショットがダウンロードされ検証されるまで、対象サービスのローカル認可判定は直ちに停止します。
- **配信を一時停止 / 配信を再開：** ローカル同期と判定を継続したまま、下流 ADS インスタンスへの配信を停止・再開します。
- **この ADS を停止：** 再起動されるまで、すべての認可リクエストを拒否し再接続を停止するよう指示します。
- **このインスタンスを削除：** インスタンス記録と履歴を削除します（稼働中のインスタンスは停止するか API キーを取り消さない限り次回接続時に再登録されます）。

## 監査ログの確認とアカウント設定

### 監査ログ

Speedle Cloud には最新順・**180 日間保持**・ページング対応の 2 種類の監査ログがあります。

- **ワークスペース監査ログ**（左サイドバー → **監査ログ**）：アクティブなワークスペース内の管理操作（サービス・ポリシー変更、API キー作成/取り消し、ADS 操作、ワークスペース変更、メンバー・招待変更）を記録します。オーナーと管理者の双方が閲覧できます。
- **個人のアクティビティ**（トップバー **アカウント** メニュー → **アカウント概要** → **個人のアクティビティ**、`/account/audit`）：サインイン、サインアウト、全デバイスからのサインアウト、ログインプロバイダーの接続/解除、アカウント作成/削除など個人イベントを記録します。

### アカウント設定

トップバーの **アカウント** メニューから **アカウント設定**（`/account/settings`）を開きます。

- **接続済みのID：** 予備のサインイン手段として **GitHub** と **Google** の両方を接続しておくことを推奨します。最低 1 つの接続済み ID を維持する必要があり、接続解除には過去 10 分以内の認証が必要です。
- **サインアウト / すべてのデバイスからサインアウト：** トップバーの **アカウント** メニューから現在のセッションまたは全セッションを終了できます。
- **アカウントの削除：** 個人アカウント、接続済み ID、自分のみが所属するワークスペース、全セッションを完全削除します。**アカウントの削除** を選択し、求められた場合は再認証のうえ `DELETE` と入力して確定します。残したいポリシーは事前にエクスポートしてください。

**アカウント削除がブロックされた場合の復旧：** 他メンバーが残っているワークスペースの唯一の **オーナー** である場合、削除は拒否されます（`last_owner`）。そのワークスペースの **メンバー** ページで別メンバーを **オーナー** に昇格してから削除してください。
