여기서는 성능 보고서를 게시하지 않으며, 결과는 하드웨어, 정책 및 고정한 버전에 따라 달라집니다.

```text
먼저 Speedle과 비교할 오픈 소스 인가 프로젝트가 무엇인지 저에게 물어보세요. 정책 집합 크기와 시간 예산도 물어보고 기본값으로 정책 10, 100, 1,000개와 30분을 제안하세요. 제가 답할 때까지 다른 작업을 하지 마세요.

그런 다음 새 로컬 디렉터리에서 같은 머신을 사용해 예산 내에서 공정하게 비교하세요. 모든 엔진과 도구의 버전을 고정하세요. 동등한 RBAC 및 ABAC 정책과 예상 허용/거부 결정이 있는 공통 요청을 만들고, 시간을 측정하기 전에 모든 엔진의 결정을 검증하세요. 의미 차이를 기록하고 지원하지 않는 사례는 직접 비교에서 제외하세요.

합의한 정책 수에 따른 확장성을 측정하세요. 정책 로딩과 안정 상태 평가를 분리하고, 임베디드 측정과 네트워크/API 측정을 분리하세요. 같은 요청, 동시 실행 수, 캐시 설정을 사용하고 각 엔진을 워밍업한 뒤 최소 5회 반복하세요. 지연 시간 p50/p95/p99와 처리량을 단위, 실행 시간, 변동과 함께 보고하세요. 실측 수치만 보고하고 실행하지 않은 사례와 실패를 명시하세요. 재현할 수 있도록 스크립트, 정책, 정확한 명령, 버전, 환경 정보, 원시 출력을 로컬에 저장하세요.
```

프롬프트를 복사해 에이전트에 붙여 넣고 질문에 답하세요.
