<a id="사용"></a>
Speedle 커뮤니티에 오신 것을 환영합니다. 사용, 홍보, 코드 기여 등 다양한 방식의 참여를 적극 환영합니다.

## 홍보

Speedle이 마음에 드신다면 [GitHub 프로젝트 페이지](https://github.com/teramoby/speedle-plus)에서 스타를 누르고 동료나 친구에게 추천해 주세요. 성공 사례 공유도 환영합니다.

<a id="토론과커뮤니티"></a>
## 토론 및 커뮤니티

[Speedle Discord 커뮤니티](https://discord.gg/uaY2xVsbbT)에 참여하여 질문하고, 아이디어를 공유하며, 코드 기여에 대해 논의하세요.

[speedle-users](https://groups.google.com/forum/#!forum/speedle-users) 및 [speedle-developers](https://groups.google.com/forum/#!forum/speedle-developers) 메일링 리스트에도 참여하실 수 있습니다.

<a id="이슈"></a>
## 문제 보고

버그나 기능 개선 제안이 있는 경우 [GitHub issue](https://github.com/teramoby/speedle-plus/issues)를 등록해 주세요.

가능한 한 다음 내용을 포함해 주시기 바랍니다:

1. Speedle 버전
2. 문제 설명
3. 재현 환경 및 단계
4. 기대 동작

<a id="code"></a>
## 코드 기여

Speedle에 대한 기여는 Universal Permissive License 1.0 (UPL-1.0)에 따라 이루어집니다. Developer Certificate of Origin (DCO) 1.1에 따라 기여를 제출할 권리가 있음을 인증하기 위해 커밋에 서명(`git commit -s`)을 남겨주세요. Pull Request에서 기존 저작권 및 라이선스 고지를 유지하고 타사 자료가 있는 경우 명시하세요.

코드 기여 절차:

1. `git commit -s`로 각 커밋에 서명([DCO](https://github.com/teramoby/speedle-plus/blob/master/DCO) 및 [UPL-1.0 LICENSE](https://github.com/teramoby/speedle-plus/blob/master/LICENSE) 참조)
2. 리포지토리 포크
3. 기존 이슈 해결 또는 이슈 생성 후 해결
4. 이슈를 해결하는 Pull Request 생성
5. CI 파이프라인 결과 확인 및 실패 수정
6. 메인테이너 검토 및 PR 병합

## 행동 강령

[Golden Rule](https://en.wikipedia.org/wiki/Golden_Rule)을 따르고 구체적인 지침은 [Contributor Covenant Code of Conduct](https://www.contributor-covenant.org/version/1/4/code-of-conduct.html)를 참조하세요.
