<a id="使用"></a>
Speedle コミュニティへようこそ。利用、普及、コードの貢献など、さまざまな形での参加を心より歓迎します。

## プロモーション

Speedle を気に入っていただけた場合は、[GitHub プロジェクトページ](https://github.com/teramoby/speedle-plus)でスターを付け、同僚や友人に推薦してください。導入事例の共有も歓迎します。

<a id="ディスカッションとコミュニティ"></a>
## ディスカッションとコミュニティ

[Speedle Discord コミュニティ](https://discord.gg/uaY2xVsbbT)に参加して、質問、アイデアの共有、コード貢献についての議論を行いましょう。

[speedle-users](https://groups.google.com/forum/#!forum/speedle-users) や [speedle-developers](https://groups.google.com/forum/#!forum/speedle-developers) メーリングリストにも参加できます。

<a id="issue"></a>
## 問題の報告

バグや機能改善の提案がある場合は、[GitHub issue](https://github.com/teramoby/speedle-plus/issues) を作成してください。

可能な限り以下を含めてください:

1. Speedle のバージョン
2. 問題の説明
3. 再現環境と手順
4. 期待される動作

<a id="code"></a>
## コードの貢献

Speedle への貢献は Universal Permissive License 1.0 (UPL-1.0) の下で行われます。Developer Certificate of Origin (DCO) 1.1 の下で貢献を提出する権利があることを証明するために、コミットにサインオフ (`git commit -s`) を付与してください。Pull Request 内で既存の著作権およびライセンス表示を保持し、サードパーティの素材があれば明記してください。

コードを貢献する手順は以下のとおりです:

1. `git commit -s` で各コミットにサインオフを付与（[DCO](https://github.com/teramoby/speedle-plus/blob/master/DCO) および [UPL-1.0 LICENSE](https://github.com/teramoby/speedle-plus/blob/master/LICENSE) を参照）
2. リポジトリをフォーク
3. 既存の issue を修正、または issue を作成して修正
4. issue を修正する Pull Request を作成
5. CI パイプラインの結果を確認し、失敗があれば修正
6. プロジェクトメンテナーが PR をレビューし、適切にマージ

## 行動規範

[Golden Rule](https://en.wikipedia.org/wiki/Golden_Rule) に従い、具体的なガイドラインについては [Contributor Covenant Code of Conduct](https://www.contributor-covenant.org/version/1/4/code-of-conduct.html) を確認してください。
