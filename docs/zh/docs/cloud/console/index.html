Speedle Cloud 控制台用户手册

在 Speedle Cloud 控制台中管理工作区、服务、策略、策略试运行、API key、函数、ADS 实例与审计日志。

    Speedle Cloud 已开放公开测试版。 免费公开测试版用于试用、学习和评估，不提供 SLA，不建议用于生产环境。功能和限额可能调整。

    本手册介绍 Speedle Cloud 控制台（SCC）（cloud.speedle.io）的日常操作流程。如需快速从服务端完成一次 API 调用，请参阅快速入门。接口载荷、错误码与配额详情请参阅授权 API、API 参考和限额与错误。

    登录与控制台布局

    前置条件

    • 启用了 JavaScript 与 Cookie 的浏览器。
    • 拥有已验证邮箱的 GitHub 或 Google 账号。

    登录或创建账号

    1. 打开 cloud.speedle.io，选择 开始使用（或直接访问 /login）。
    2. 选择 使用 GitHub 登录 或 使用 Google 登录，并在登录提供方处完成身份验证。
    3. 如果这是你首次使用尚未绑定的已验证邮箱登录，请查看服务条款与隐私政策链接，并确认 创建账号。

    预期结果： 控制台打开当前工作区的 服务与策略 页面（路径为 /w/<workspaceId>/service）。新账号默认带有一个名为 个人 的工作区，你在其中的角色为 所有者。

    故障恢复：

    • 此邮箱已有账号： 请先用控制台提示的已关联登录方式登录，再前往 账号设置 关联第二种登录方式。
    • 需要已验证邮箱： 请先在 GitHub 或 Google 账号设置中完成邮箱验证，再重新登录。
    • 暂停新用户注册： 公测版已达到新账号上限；已有账号仍可正常登录。
    • 会话已结束： 会话在连续 7 天无活动或创建满 30 天时失效（以先到者为准），重新登录即可继续。

    控制台导航

    登录后的控制台包含两个主要导航区域：

    • 顶部栏：
      • Speedle | Cloud 标志：返回当前工作区的 服务与策略。
      • 工作区 切换器：显示当前工作区名称与你的角色（所有者 或 管理员），用于切换工作区或 新建工作区。
      • 需要帮助？ 链接、语言 切换器和 账号 菜单（显示邮箱、账号概览、账号设置、退出登录 和 在所有设备上退出）。
    • 左侧导航栏：
      • 控制台： 服务与策略、API key、ADS 舰队 与 审计日志——均作用于当前选中的工作区。
      • 工作区设置： 成员——查看或管理当前工作区成员。
      • Cloud 文档： 打开本文档站点。

    个人身份与工作区

    Speedle Cloud 将个人账号与工作区清晰分离：

    • 个人账号保存你的已验证邮箱、已关联的登录方式（GitHub 和/或 Google）、浏览器会话以及 个人活动 日志（/account/audit）。
    • 工作区是隔离的资源容器，包含服务、授权与角色策略（含 全局角色）、自定义函数、API key、ADS 舰队实例、工作区 审计日志 以及每日 API 调用额度。

    每个账号默认拥有一个 个人 工作区。每人最多可加入 10 个工作区；每个工作区最多包含 10 名成员（待接受的邀请计入上限）。

    切换或新建工作区

    1. 在顶部栏打开 工作区 菜单。
    2. 选择已有工作区进行切换，或选择 新建工作区。
    3. 创建工作区时，输入 工作区名称（1–64 个字符），然后选择 新建工作区。

    预期结果： 新工作区从空开始，拥有独立的服务、策略、API key 和每日配额，你自动成为其 所有者。页面地址切换为 /w/<workspaceId>/service。切换工作区会清除屏幕上正在展示的一次性密钥。

    管理工作区成员与角色

    在左侧导航栏打开 工作区设置 → 成员。

    角色 权限说明
    所有者 具备管理员的全部权限，还可邀请成员、撤销待接受的邀请、调整成员角色以及移除成员。
    管理员 管理服务、策略、导入与导出、函数、策略试运行、API key 与 ADS 舰队；查看成员列表和工作区审计日志；退出工作区。

    邀请成员（仅所有者）：

    1. 在 邀请成员 区域输入对方的 邮箱地址，并选择 角色（管理员 或 所有者）。
    2. 选择 发送邀请。

    预期结果： 系统向该邮箱发送包含一次性邀请链接（7 天有效）的邮件，并在 待接受的邀请 中列出（计入 10 名成员上限；每人每个 UTC 日最多发出 20 份邀请）。所有者可看到完整受邀邮箱，管理员看到的是脱敏邮箱。如需取消待接受的邀请，选择该行旁的 撤销。

    受邀人打开邮件中的链接，使用已验证该邮箱的 GitHub 或 Google 账号登录，然后选择 加入工作区 即可完成加入。

    调整角色、移除成员或退出工作区：

    • 调整角色（仅所有者）： 通过成员旁的 角色 下拉框，将管理员提升为所有者，或将所有者降级为管理员。
    • 移除成员（仅所有者）： 选择 移除，阅读提示后确认 移除成员。该成员从下一次请求起失去访问权。
    • 退出工作区： 选择 退出工作区 并确认。

    成员离开或被移除后，其创建的 API key 仍保持有效。 API key 属于工作区而非创建者个人。移除成员后，控制台会列出该成员创建且仍在有效的 API key（名称、ID 和到期时间，不显示密钥明文）。请前往 API key 页面核对并按需撤销或轮换。

    故障恢复：

    • 验证你的身份（reauth_required）： 调整角色、移除成员和退出工作区需要最近 10 分钟内的登录验证。请通过已关联的登录方式验证身份，然后重新执行操作。
    • 最后一名所有者（last_owner）： 工作区至少必须保留一名所有者。请先将另一名成员提升为 所有者，再降级自己或退出工作区。
    • 邀请邮箱不匹配或链接失效： 请受邀人使用已验证受邀邮箱的 GitHub 或 Google 账号登录（GitHub 的任一已验证邮箱均可）；若 7 天链接已过期或被撤销，请由所有者重新发送邀请。

    管理服务与策略

    以下示例使用名为 books 的服务，并在其中创建一条角色分配策略和一条授权策略。

    创建服务

    1. 在左侧导航栏打开 服务与策略。
    2. 如果工作区尚无服务，直接输入 服务名称 books 并选择 创建服务。如果已有服务，打开 当前服务 选择器，选择 添加服务，输入 books 并选择 创建服务。

    服务名称需为 1–64 个字符，仅允许字母、数字、点、下划线或连字符，且以字母或数字开头。名称 global 保留给 全局角色。应用在授权请求中通过 serviceName 传入该名称。

    创建授权策略与角色策略

    1. 选中 books 后，在 策略 标签页选择 创建策略。
    2. 可选填写 策略名称（最多 128 个 Unicode 字符，如 reader-role）；留空将自动生成名称。
    3. 在 SPDL 源码 中输入一条 SPDL 策略语句（UTF-8 编码不超过 1,024 字节）：
    grant user alice from corp Reader
    1. 稍作停顿，编辑器会自动进行实时语法校验，并显示识别到的策略类型（有效 · 角色策略 或 有效 · 授权策略），以及语法错误或检查提示（如未授予权限的角色、未锚定的正则表达式等）。
    2. 选择 保存策略。
    3. 重复上述步骤，创建一条授权策略（如 read-books）为该角色授予权限：
    grant role Reader get /books

    预期结果： 两条策略都会出现在 books 的策略列表中。已保存的策略会立即在 策略试运行 中生效，并约在 60 秒内同步到托管授权 API。

    你可以在代码编辑器与 使用纯文本编辑器 之间切换，按效果、主体、动作、资源、角色或是否包含条件搜索和筛选策略列表，并在每行执行 编辑、详情、测试 或 删除。

    使用全局角色跨服务分配角色

    当同一工作区内的多个服务共享同一角色分配时，可在 全局角色 中定义一次：

    1. 打开 当前服务 选择器，选择列表顶部的 全局角色。
    2. 创建一条角色策略，例如 grant user alice from corp BookAdmin。
    3. 切换到需要识别该角色的普通服务（如 books），创建为 BookAdmin 授予权限的授权策略。

    全局角色 仅接受角色策略，且不可重命名或删除。全局角色本身不授予任何操作权限，各普通服务仍需自行定义对应的授权策略。详细规则与 ADS 同步说明见全局角色。

    在权限关系图中查看策略关系

    在 服务与策略 中切换到 权限关系图 标签页，可直观查看当前服务已保存策略中主体、角色与资源的关联。你可以筛选图谱、切换表格视图、聚焦特定节点，并将某条路径直接带入 策略试运行 执行 诊断。

    导入与导出策略

    在 服务与策略 中切换到 导入与导出 标签页：

    • 下载 SPDL 或 下载 JSON： 导出当前服务已保存的策略数据。请妥善保管导出文件，并在公测期间自行维护备份。
    • 导入策略： 选择 Speedle Cloud 导出的 JSON 文件（不超过 32 MiB），核对预览统计后选择 确认导入策略。导入是原子操作：已有策略不会被修改，且允许显示名称重复（包括同批次内重复或与已有策略同名），因为每条导入的策略都会获得服务端新生成的唯一 ID。只有存在无效策略或总数超过工作区 200 条策略上限时，整批导入才会被拒绝。

    如果导入过程中网络中断或结果未确认，请保持页面打开并使用 重试同一批导入——它会复用同一个幂等键，避免重复写入已确认的策略。如果在导入已完成后重新发起一次新导入（使用新的幂等键），会创建重复策略并占用策略名额。

    重命名或删除服务

    点击服务标题旁的 服务操作 菜单：

    • 重命名…： 修改服务名称。策略 ID、API key 和 ADS 实例身份均保持不变，但调用方应用必须将 serviceName 更新为新名称，且变更传播并非即时完成。
    • 删除服务…： 永久删除该服务及其全部策略，并从关联的 ADS 实例中移除。输入服务名称以确认。删除服务需要最近 10 分钟内的身份验证；如系统提示，请先通过已关联的登录方式验证身份，返回后再次确认删除。工作区 API key 与 ADS 实例会保留。

    故障恢复：

    • 编辑无法变更策略类型： 已保存的授权策略不能直接改写为角色策略（反之亦然）。如需更改类型，请删除后重新创建。
    • 策略版本过期： 如果你在编辑期间其他会话修改或删除了该策略，草稿会保留在页面上。请先刷新工作区，打开最新版本后再保存。
    • 修订号已达上限（revision_exhausted）： 导出该服务的策略，创建新服务，导入导出文件，将调用方切换到新的 serviceName，之后可按需删除旧服务。详见限额与错误。

    在策略试运行中测试判定

    1. 在 服务与策略 中选中 books，切换到 策略试运行 标签页。
    2. 选择 操作类型：
      • 是否允许： 返回允许或拒绝以及原因代码。
      • 诊断： 返回判定结果，并展示各策略、角色与条件的匹配轨迹。
      • 已授予的角色： 列出该主体在此服务下获得的所有角色（含全局角色）。
      • 已授予的权限： 列出该主体获准访问的所有资源和操作。
    3. 填写测试输入：
      • 主体（JSON）： [{"type":"user","name":"alice","idd":"corp"}]
      • 资源： /books
      • 操作： get
      • 属性（JSON）： []
    4. 选择 运行测试。

    预期结果： 是否允许 显示 允许。、原因 命中允许策略。 以及完整 JSON 结果。将 操作 改为 delete 后重新运行，会显示 拒绝。 和 没有匹配的策略。。

    你也可以在策略列表行点击 测试，或从 权限关系图 预填诊断请求；预填仅填充输入框，在点击 运行测试 前不会消耗 API 额度。

    注意事项：

    • 策略试运行只使用已保存的策略，不包含编辑器里尚未保存的草稿。
    • 每次运行消耗当前工作区每日额度中的 1 次 API 调用，不会修改策略。
    • 直接对 全局角色 服务运行判定总是拒绝；请在具体普通服务的策略试运行中测试全局角色。
    • 策略试运行通过不代表已发布快照已同步到所有托管节点；调用托管授权 API 前请预留约 60 秒传播时间。

    管理工作区 API key

    API key 用于让服务端应用和自托管 ADS 实例访问当前工作区。管理 API key 始终需要已登录的控制台会话。

    创建 API key

    1. 在左侧导航栏打开 API key。
    2. 选择 创建 API key。
    3. 输入便于识别的 API key 名称（1–128 个字符，例如 books-app），不要在名称中填写密钥。
    4. 选择 权限范围（创建后不可修改）：
      • 仅判定接口（ADS）（ads，默认）：仅可调用 /authz-check/v1/*。
      • 策略管理：读取（pms:read）：读取工作区内的服务和策略。
      • 策略管理：写入（pms:write）：读取、创建和删除工作区内的服务和策略。
      • ADS 同步（pms:read+ads）：供 Speedle Cloud ADS（speedle-cloud）同步策略快照、读取策略并执行授权检查，不可写入。
    5. 选择 有效期（1 周、1 个月、3 个月［默认］、6 个月 或 1 年），并确认 预计到期时间（UTC）。不支持永不过期的密钥。
    6. 选择 创建 API key。创建密钥需要最近 10 分钟内的登录验证；如系统提示，请选择 使用 GitHub 验证 或 使用 Google 验证，返回后再次提交 创建 API key。
    7. 立即复制 一次性 API key，保存到应用服务端的密钥管理服务（例如环境变量 SPEEDLE_API_KEY），然后选择 我已保存，清除本次展示。

    预期结果： 新密钥出现在 有效的 API key 列表中，显示 ID、权限范围、创建时间、近似最近使用时间和 到期时间（UTC）。密钥明文仅此一次展示，无法从元数据找回。

    轮换与撤销 API key

    每个工作区所有权限范围合计最多保留 10 个有效的 API key。7 天内到期的密钥会标记为 即将到期；已到期的密钥归入 已过期的 API key 分组。

    无中断轮换密钥的步骤：

    1. 创建具有所需权限范围和有效期的新密钥。
    2. 更新应用或 ADS 配置以使用新密钥。
    3. 在 API key 页面找到旧密钥，选择 撤销，核对名称和 ID 后确认 撤销 API key。

    故障恢复：

    • 生效延迟： 验证缓存最长可继续生效 60 秒，因此撤销不会在全球瞬间生效。
    • 达到数量上限（quota_exceeded）： 撤销不再使用的密钥，或等待即将到期的密钥自然过期以释放名额。已撤销和已过期的密钥仍保留在历史分组中，不计入 10 个有效上限。
    • 创建或撤销结果未确认： 若网络中断导致结果不明，请先刷新列表并核对有效与历史分组后再决定下一步操作，切勿仅凭名称相同判断或盲目重复创建。

    完整接口与生命周期说明见 API 密钥。

    查看用量与配额

    公开测试版中，资源上限与每日调用额度均按工作区计算：

    • 服务数： 每个工作区 100 个（包含 全局角色）。
    • 策略数： 工作区内所有服务的授权策略与角色策略合计 200 条（单条 SPDL 语句不超过 1,024 UTF-8 字节）。
    • 有效 API key： 每个工作区所有权限范围合计 10 个。
    • 每日 API 调用： 每个工作区每个 UTC 日 10,000 次（00:00 UTC 重置）。策略管理读写、实时语法校验、策略试运行、导入导出与授权检查共享该额度。

    在控制台中查看用量：

    • 账号 → 账号概览（/account）： 展示个人工作区的 每日额度 卡片、进度条和下次 UTC 重置时间。
    • 服务与策略： 显示当前工作区的服务数、策略数，并在执行工作区操作后显示当日剩余调用次数估计值。

    如遇每日额度耗尽（429 daily_quota_exceeded），请等待 00:00 UTC 重置；在同一工作区内更换 API key 不会增加额度。突发限流与错误恢复见限额与错误。

    自定义函数（按服务配置）

    当环境开启自定义函数功能时，普通服务会在 权限关系图 与 策略试运行 之间显示 函数 标签页。

    自定义函数允许 SPDL 条件在判定时调用外部 HTTPS 端点。每个普通服务最多可登记 20 个函数。

    登记与管理函数

    1. 选择一个普通服务并打开 函数 标签页。
    2. 选择 登记函数。
    3. 配置以下选项：
      • 名称： 1–64 个字符的 SPDL 标识符（不可使用保留字）。
      • 端点 URL： 接收条件参数的 HTTPS 端点（不超过 2,048 字节 UTF-8；不支持明文 HTTP）。控制台本身从不调用该端点。URL 校验规则取决于 调用位置：
        • 托管与 ADS： 仅接受默认 443 端口上的 https:// 公开非保留 DNS 主机名（至少两级标签；拒绝 IP 字面量、非 443 端口以及 localhost、*.local、*.internal、*.home.arpa、.test、.example、.invalid、.alt、.onion 等内部或保留主机名）。
        • 仅 ADS： 要求使用 https://，允许任意端口以及 IP 字面量或私有/内部主机名（例如 https://10.20.30.40:8443/func/check）。
        • 两种模式均拒绝用户信息（user@host）、片段（#...）、空白字符、控制字符和反斜杠。
      • 调用位置： 托管与 ADS（托管判定、策略试运行和自托管 ADS 均可调用）或 仅 ADS（仅自托管 ADS 调用；托管判定与策略试运行执行到该函数时会判定失败）。
      • 声明类型（可选）： 最多声明 16 个 参数 类型和一个 结果 类型。未声明参数时不校验实参类型；已声明的类型不匹配会导致判定失败。
      • 缓存结果（可选）： 求值器本地缓存 TTL（1–86,400 秒；失败结果不缓存）。
      • 托管超时（毫秒）： 100–2,000 毫秒（默认 1,000 毫秒），仅适用于托管调用。
      • 签名托管请求（可选）： 仅为托管 Cloud 请求启用 HMAC 签名。即使选择了 托管与 ADS，自托管 ADS 发出的请求也始终不带签名。
    4. 选择 保存函数。若启用了签名，请在关闭弹窗前复制并妥善保存仅显示一次的 签名密钥。

    在函数列表中，你可以 编辑 函数、轮换签名密钥（旧密钥立即失效，可能需要近期身份验证）或 删除函数。

    重要规则与故障恢复：

    • function_url_rejected： 确认 URL 使用 https:// 且不含用户信息、片段、空白或反斜杠。如需使用 IP、内部主机名或非 443 端口，请将调用位置切换为 仅 ADS；使用 托管与 ADS 时，请改为 443 端口的公开 DNS 主机名。
    • 保存或导入引用自定义函数的策略之前，必须先在目标服务中登记该函数。策略导出文件不包含函数定义。
    • 仍被策略引用的函数无法删除，请先修改或删除引用策略。

    监控与控制 ADS 舰队

    在左侧导航栏打开 ADS 舰队，查看从当前工作区同步策略的自托管 Speedle Cloud ADS（speedle-cloud）实例。Cloud 不会主动连入你的网络，所有控制命令均通过实例主动建立的通道下发。

    接入第一个 ADS 实例

    无需预先注册。当舰队为空时，ADS 舰队 页面会展示三步接入指引与可复制的配置片段：

    1. 在 API key 页面创建一个 ADS 同步（pms:read+ads）范围的密钥。
    2. 将密钥写入 ADS 配置文件（权限设为 0600），并将 CacheDir 放在持久卷上以在重启后保留同一实例身份。
    3. 配置应用监听器 TLS 并启动 speedle-cloud。实例首次连接后会自动出现在 ADS 舰队 中。

    每个工作区最多允许 10 个 ADS 实例同时在线，最多保留 100 条实例记录（离线超过 7 天的实例会自动移除）。

    查看实例详情与执行分发操作

    可使用 服务筛选 查看同步特定服务的实例，或点击 刷新舰队 立即更新（页面可见时每 5 分钟自动刷新）。

    点击实例行的 详情，可查看：

    • 实时状态、最近收到心跳（UTC）、通道 与 传输（WebSocket 或长轮询）。
    • 服务集合，包括 head 修订号、已上报修订号、同步延迟以及 全局角色（始终同步）。
    • 分发链路（上游与直连下游实例）、事件时间线、兜底历史 及实例上报的 主机 信息。

    支持的分发操作（均需确认）：

    • 分配服务： 选择同步 全部服务，包括以后创建的服务 或 仅所选服务。变更会随下一次心跳送达，无需重启 ADS。
    • 从快照重新同步： 让实例丢弃本地副本并从快照重新加载。可用性影响： 受影响的服务会立即停止本地授权判定，直到下载并验证完新的快照后才恢复。
    • 暂停分发 / 恢复分发： 暂停或恢复向下游 ADS 实例提供策略；实例自身的本地同步与判定不受影响。
    • 停止此 ADS： 指示实例拒绝所有授权请求并停止重连，直至人工重启。
    • 删除此实例： 删除实例记录与历史（仍在运行的实例会在下次连接时重新注册；如需彻底阻止，请先停止实例或撤销其 API key）。

    查看审计日志与管理账号设置

    审计日志

    Speedle Cloud 提供两类独立的审计日志，均按时间倒序排列、保留 180 天 并支持分页（上一页、下一页、从第一页重新查看）：

    • 工作区审计日志（左侧导航栏 → 审计日志）：记录当前工作区内的管理操作——服务与策略变更、API key 创建与撤销、ADS 操作、工作区创建与重命名以及成员和邀请变更。所有者与管理员均可查看。
    • 个人活动（顶部栏 账号 菜单 → 账号概览 → 个人活动，路径 /account/audit）：记录个人账号事件——登录、退出登录、在所有设备上退出、关联或取消关联登录方式以及账号创建与删除。

    账号设置

    打开顶部栏 账号 菜单并选择 账号设置（/account/settings）：

    • 已关联的登录方式： 建议同时关联 GitHub 和 Google 作为备用登录方式。账号必须至少保留一种登录方式；取消关联需要最近 10 分钟内的身份验证。
    • 退出登录 / 在所有设备上退出： 在顶部栏 账号 菜单中可退出当前浏览器会话或全部设备上的会话。
    • 删除账号： 永久删除个人账号、已关联登录方式、仅由你一人拥有的工作区以及所有会话。选择 删除账号，按提示验证身份后输入 DELETE 并确认 永久删除账号。删除前请先导出需要保留的策略。

    删除账号受阻时的恢复： 如果你是某个仍有其他成员的工作区的唯一 所有者，系统会阻止删除账号（last_owner）。请先前往该工作区的 成员 页面，将另一名成员提升为 所有者 后再删除账号。
