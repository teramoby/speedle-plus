SDK

Speedle SDK 是决策 API POST /authz-check/v1/is-allowed 的客户端库，既可用于自托管的 Speedle ADS，也可用于 Speedle Cloud。每个语言页面说明如何添加软件包，并分别给出两种场景下经过实测的完整程序。源代码和完整参考见 teramoby/speedle-sdk。

软件包

Java、Python、Go、.NET 和 Rust 的版本均为 0.2.0。@speedle/sdk 已在 npm 发布。安装命令见各语言页面。

  • Java：Maven Central io.speedle:speedle-sdk，已发布。
  • Python：PyPI speedle，已发布。
  • Go：Go 模块 github.com/teramoby/speedle-sdk/go，已发布。
  • C#/.NET：NuGet Speedle.Sdk，已发布。
  • Rust：crates.io speedle，已发布。
  • Node.js / TypeScript：npm @speedle/sdk，已发布。

Docker 镜像

Docker 镜像 用 docker.io/speedle/speedle 或 ghcr.io/teramoby/speedle 运行 speedle-pms、speedle-ads 和 spctl。把 ADS 发布到 127.0.0.1:6734，本页的客户端指向这个端口即可。

功能

功能 状态
isAllowed：返回授权结果 六个 SDK 均支持
check：返回授权结果及原因，例如没有适用的策略 六个 SDK 均支持
自托管 Speedle ADS 六个 SDK 均支持
Speedle Cloud 即将上线

方法名遵循各语言的命名习惯：Python 和 Rust 中为 is_allowed 与 check，Go 中为 IsAllowed 与 Check，.NET 中为 IsAllowedAsync 与 CheckAsync。

其他操作（如查询已授予的权限、诊断和策略管理）请使用 REST API：授权决策 API 和策略管理 API。

示例策略

所有示例都检查服务 docs 中的用户 alice 能否对资源 /docs/public 执行 get 和 delete。要在本地 Speedle 上得到文档中的结果，先按快速入门构建 Speedle，在 6733 端口启动 PMS、在 6734 端口启动 ADS，然后创建服务和策略：

./bin/spctl --pms-endpoint http://127.0.0.1:6733/policy-mgmt/v1/ create service docs
./bin/spctl --pms-endpoint http://127.0.0.1:6733/policy-mgmt/v1/ create policy -c "grant user alice get,list /docs/public" --service-name=docs

本地示例以无凭据方式连接 http://localhost:6734。SDK 只对回环地址接受明文 http://；连接其他 ADS 时请使用 HTTPS。

Speedle Cloud 即将上线。 Speedle Cloud 示例连接 https://cloud.speedle.io，并从环境变量 SPEEDLE_SERVICE 和 SPEEDLE_TOKEN 读取服务名及该服务专属的令牌。在该服务中创建同样的策略即可得到相同的结果。令牌是服务端密钥，切勿放进浏览器、移动应用或桌面客户端。
