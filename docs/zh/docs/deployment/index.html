部署

Speedle 可以嵌入 Go 应用，也可以用一个已发布的容器镜像运行，或者作为独立的 PMS 和 ADS 服务运行。

  • 嵌入模式 在 Go 进程内运行决策引擎。
  • Docker 镜像 用 docker.io/speedle/speedle 或 ghcr.io/teramoby/speedle 运行 speedle-pms、speedle-ads 和 spctl。
  • Homebrew 安装命令行工具和两个服务，并在本机做一次演示。

选择部署方式

通过嵌入模式可以在 Go 进程内运行决策引擎。应用通过 REST 或 gRPC 调用 Speedle 时，可以使用Docker 镜像，也可以运行独立的 PMS 和 ADS。Homebrew 安装这些程序并在本机做一次演示。快速入门提供了完整的本地策略管理和授权验证步骤。

使用当前 Go 版本构建

在 Linux 或 macOS 上准备 Go 1.26.10 或 Go 1.27.3（也可使用同一大版本的更新补丁版本）（推荐 Go 1.27.3）、Git 和命令行 shell。使用 Go modules，源码可放在任意可写目录，无需手工配置 GOROOT、GOPATH、dep 或 GOPATH 源码路径。

git clone --depth 1 https://github.com/teramoby/speedle-plus.git
cd speedle-plus
mkdir -p bin
go build -o ./bin/ ./cmd/spctl ./cmd/speedle-pms ./cmd/speedle-ads

生成的可执行文件为 bin/spctl、bin/speedle-pms 和 bin/speedle-ads。从源码根目录运行下面的本地示例，两个服务共享同一策略文件：

./bin/speedle-pms --store-type file --filestore-loc ./docs-policies.json --endpoint 127.0.0.1:6733 --insecure=true

保持 PMS 运行，在同一源码目录的另一个终端启动 ADS：

./bin/speedle-ads --store-type file --filestore-loc ./docs-policies.json --endpoint 127.0.0.1:6734 --insecure=true

使用新的策略文件；文件不存在时 PMS 会创建它。创建策略和验证 Allow/Deny 的完整请求见快速入门，结束后用 Ctrl+C 停止两个服务。默认关闭 gRPC，只有设置 --grpc-endpoint 才启用。此处明文 HTTP 仅用于本机示例，TLS 和客户端认证见安全配置。

发布二进制与容器映像

发布流程生成的每个发布版本都会附带适用于 macOS 和 Linux（amd64、arm64）的 spctl、speedle-pms 和 speedle-ads 预编译二进制，文件名格式为 <命令>_<系统>_<架构>，并附带 checksums.txt。请从 Releases 页面下载，运行前先用 SHA-256 校验和核对每个文件；校验和文件与二进制位于同一发布版本中，只能用于发现下载不完整或文件损坏，不能验证发布内容是否遭到篡改。二进制和容器映像都由发布流程生成，因此从该流程加入后的第一个发布版本开始提供。

发布流程还会发布两个面向 Linux amd64 和 arm64 的多架构容器映像：

  • ghcr.io/teramoby/speedle-pms
  • ghcr.io/teramoby/speedle-ads

匿名拉取要求 GHCR 软件包为公开；如果软件包是私有的，请先执行 docker login ghcr.io 登录。

请拉取要部署的发布版本；latest 跟随最新发布版本：

docker pull ghcr.io/teramoby/speedle-pms:latest
docker pull ghcr.io/teramoby/speedle-ads:latest

需要按摘要固定时，可用 docker buildx imagetools inspect ghcr.io/teramoby/speedle-pms:<标签> 查看发布映像的摘要。

两个映像都以 UID 65532 运行服务，并包含可写的 /data 目录用于文件存储。在映像名之后传入服务参数，每条命令各用一个终端运行：

docker run --rm -p 127.0.0.1:6733:6733 -v speedle-policies:/data ghcr.io/teramoby/speedle-pms:latest --store-type file --filestore-loc /data/policies.json --endpoint 0.0.0.0:6733 --insecure=true
docker run --rm -p 127.0.0.1:6734:6734 -v speedle-policies:/data ghcr.io/teramoby/speedle-ads:latest --store-type file --filestore-loc /data/policies.json --endpoint 0.0.0.0:6734 --insecure=true

PMS 没有内置的调用方身份认证；127.0.0.1 绑定把未认证的管理 API 限制在本机。请勿将这些端口发布到主机网络接口，也不要暴露给不受信任的网络。

映像不包含 CA 证书；连接 TLS 端点时需要提供 CA 文件。--insecure=true 仅用于本机示例，详见安全配置。

Kubernetes 开发示例

使用当前 Kubernetes 集群和兼容的 kubectl。将以下内容保存为 speedle-dev.yaml。它使用 apps/v1，在同一 Pod 内让 PMS/ADS 共享文件，以非 root 用户运行应用，并通过内部 ClusterIP 服务访问。这是隔离开发环境示例：Pod 替换后，emptyDir 中的策略会丢失，HTTP 端点需要集群访问控制。清单中的映像使用 <release-tag> 占位符；部署时请替换为要使用的发布标签，或使用摘要（digest）实现不可变固定；集群需要时配置 imagePullSecrets。

apiVersion: apps/v1
kind: Deployment
metadata:
  name: speedle-dev
spec:
  replicas: 1
  strategy:
    type: Recreate
  selector:
    matchLabels:
      app: speedle-dev
  template:
    metadata:
      labels:
        app: speedle-dev
    spec:
      initContainers:
        - name: policy-file
          image: busybox:1.37.0
          command: ["sh", "-c", "printf '{}\n' > /data/policies.json; chown 65532:65532 /data/policies.json; chmod 600 /data/policies.json"]
          volumeMounts:
            - name: policies
              mountPath: /data
      containers:
        - name: pms
          image: ghcr.io/teramoby/speedle-pms:<release-tag>
          args: ["--store-type", "file", "--filestore-loc", "/data/policies.json", "--endpoint", "0.0.0.0:6733", "--insecure=true"]
          ports:
            - containerPort: 6733
          readinessProbe:
            tcpSocket:
              port: 6733
          volumeMounts:
            - name: policies
              mountPath: /data
        - name: ads
          image: ghcr.io/teramoby/speedle-ads:<release-tag>
          args: ["--store-type", "file", "--filestore-loc", "/data/policies.json", "--endpoint", "0.0.0.0:6734", "--insecure=true"]
          ports:
            - containerPort: 6734
          readinessProbe:
            tcpSocket:
              port: 6734
          volumeMounts:
            - name: policies
              mountPath: /data
      volumes:
        - name: policies
          emptyDir: {}
---
apiVersion: v1
kind: Service
metadata:
  name: speedle-dev
spec:
  type: ClusterIP
  selector:
    app: speedle-dev
  ports:
    - name: pms
      port: 6733
      targetPort: 6733
    - name: ads
      port: 6734
      targetPort: 6734

将 PMS_IMAGE、ADS_IMAGE 设置为实际部署的完整映像，例如发布标签或摘要（digest）。先在本地替换清单中的映像，再应用；使用快速入门客户端时保持端口转发运行：

kubectl set image --local -f speedle-dev.yaml pms="$PMS_IMAGE" ads="$ADS_IMAGE" -o yaml | kubectl apply -f -
kubectl rollout status deployment/speedle-dev
kubectl port-forward service/speedle-dev 6733:6733 6734:6734

生产部署

生产环境应使用持久化策略存储，将容器映像摘要（digest）固定到要部署的发布版本（发布重试可能重新推送版本标签），保护管理与决策端点，并为客户端和策略后端配置 TLS/mTLS。当前存储配置见可插拔存储，传输参数见安全配置。请按当前 etcd 文档部署和运维 etcd，不要继续使用已停止维护的 etcd-operator 示例。

仓库中保留了历史 Helm/Kubernetes 示例。旧的 Helm 2 helm install -n ...、stable/etcd-operator、apps/v1beta2 和 r.authz.fun 映像说明均不是本页的新部署流程。容器拉取、集群准入、仓库访问、存储与 rollout 依赖具体环境，应在目标集群中验证后再用于生产。
