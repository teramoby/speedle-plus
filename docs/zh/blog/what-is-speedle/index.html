为什么选择 Speedle？

是什么，为什么？

一些思考： 授权并不是新概念，软件一直在使用它。不同系统陆续形成了各自的授权方案，例如 Kubernetes、Istio 和各种 IAM 系统；本地应用可能还在使用其他方案。当应用逐渐采用混合部署、跨环境工作负载或不同云厂商时，如何跟踪和管理分散在这些系统中的策略与身份？Speedle 通过多种集成方式提供集中管理，还可以根据服务间的交互实时发现相关策略，并快速执行决策。

早期内容

有三个问题想请你考虑。

  1. 你的系统需要授权吗？如果不需要，就不需要 Speedle。
  2. 如果需要，你是否希望自己设计策略模型并实现全部授权功能？如果更愿意自己实现一套授权方案，就不需要 Speedle。

  3. 如果你希望采用现有产品，可以比较下面几个选择。我们不会只告诉你 Speedle 具备灵活的策略模型、易用的策略语言、高效可扩展的决策引擎和活跃社区，而是希望你亲自评估并选择适合自己的方案。
