Node.js/TypeScript SDK

Install @speedle/sdk with npm, then call isAllowed and check against a local Speedle or Speedle Cloud.

    The Node.js SDK needs Node.js 22 or later, ships ESM and CommonJS builds with TypeScript types, and has no runtime dependencies. Package: @speedle/sdk, published on npm. Reference: speedle-sdk/node.

    The examples check the policy described in the SDKs overview.

    Add the dependency

    In a new ES module package:

    mkdir speedle-example
cd speedle-example
npm init -y
npm pkg set type=module
npm install @speedle/sdk@0.2.1

    Call a local Speedle

    Start Speedle and create the example policy as described in the SDKs overview. Save this program as main.ts:

    import { Auth, Reason, SpeedleClient, SpeedleError } from "@speedle/sdk";

try {
  const speedle = new SpeedleClient({
    backend: "speedle",
    endpoint: "http://localhost:6734",
    auth: Auth.none(),
    serviceName: "docs",
  });
  try {
    const allowed = await speedle.isAllowed("alice", "get", "/docs/public");
    console.log(`alice get /docs/public: allowed=${allowed}`);

    const d = await speedle.check("alice", "delete", "/docs/public");
    console.log(`alice delete /docs/public: allowed=${d.allowed} reason=${Reason[d.reason] ?? d.reason}`);
  } finally {
    await speedle.close();
  }
} catch (e) {
  if (!(e instanceof SpeedleError)) throw e;
  console.error(`Speedle error: ${e.message}`);
  process.exitCode = 1;
}

    Run it. Node.js 22.18 or later runs TypeScript files directly:

    node main.ts

    Output:

    alice get /docs/public: allowed=true
alice delete /docs/public: allowed=false reason=NoApplicablePolicies

    Call Speedle Cloud

    Speedle Cloud is coming soon.

    The program reads the service name from SPEEDLE_SERVICE and an account API key with the ads scope from SPEEDLE_TOKEN. SPEEDLE_ENDPOINT overrides the default endpoint https://cloud.speedle.io. Replace main.ts with:

    import { Auth, Reason, SpeedleClient, SpeedleError } from "@speedle/sdk";

try {
  const speedle = new SpeedleClient({
    backend: "speedle-cloud",
    endpoint: process.env.SPEEDLE_ENDPOINT ?? "https://cloud.speedle.io",
    auth: Auth.bearer(process.env.SPEEDLE_TOKEN ?? ""),
    serviceName: process.env.SPEEDLE_SERVICE ?? "",
  });
  try {
    const allowed = await speedle.isAllowed("alice", "get", "/docs/public");
    console.log(`alice get /docs/public: allowed=${allowed}`);

    const d = await speedle.check("alice", "delete", "/docs/public");
    console.log(`alice delete /docs/public: allowed=${d.allowed} reason=${Reason[d.reason] ?? d.reason}`);
  } finally {
    await speedle.close();
  }
} catch (e) {
  if (!(e instanceof SpeedleError)) throw e;
  console.error(`Speedle error: ${e.message}`);
  process.exitCode = 1;
}

    Set the environment and run it. read -rs keeps the API key out of your shell history and screen:

    export SPEEDLE_SERVICE=docs
read -rs SPEEDLE_TOKEN && export SPEEDLE_TOKEN
node main.ts

    Output, when the service has the example policy:

    alice get /docs/public: allowed=true
alice delete /docs/public: allowed=false reason=NoApplicablePolicies

    The API key is a server-side secret. Never ship it to browsers, mobile apps or desktop clients.

    Speedle MCP

    @speedle/mcp is published on npm. Speedle MCP (launch preview) is one package with check and manage modes. Install it with npm:

    npm install @speedle/mcp@0.2.1

    Or run the speedle-mcp binary directly:

    npx @speedle/mcp@0.2.1 check

    Running speedle-mcp without a mode prints usage and exits with a non-zero status. Reference: speedle-mcp.

    Error handling

    A denied request is not an error: isAllowed resolves to false, and check resolves to a decision with allowed false and the reason, as in the delete call above. With the default settings, when a call cannot return a decision, the promise rejects with SpeedleError. The examples catch it, print Speedle error: <message> to standard error and set process.exitCode = 1; any other error is rethrown.
