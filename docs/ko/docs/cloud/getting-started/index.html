Speedle Cloud 빠른 시작

    Speedle Cloud는 출시 예정입니다. cloud.speedle.io의 프로덕션 환경에서는 아직 로그인이 시작되지 않았으며 Cloud 헤더에는 Coming soon(출시 예정) 배지가 표시됩니다. 로그인이 닫혀 있는 동안 로그인 페이지에는 곧 출시될 예정이라는 안내가 표시됩니다. 본문에서는 공개된 사용 흐름을 설명하지만 현재 프로덕션 콘솔이 열려 있음을 의미하지는 않습니다.

    프로덕션 환경

    계정 세션, 관리 요청 및 애플리케이션 토큰은 https://cloud.speedle.io를 사용합니다. 계정, 리소스, 토큰은 해당 오리진에 속합니다.

    GitHub 또는 Google을 통한 로그인(출시 예정)

    로그인이 아직 시작되지 않았더라도 로그인 페이지에는 GitHub로 로그인과 Google로 로그인이라는 두 가지 옵션이 표시됩니다. 프로덕션 환경에서 로그인이 시작되면 현재 사용 가능한 공급자를 선택하십시오. 새 ID의 인증된 이메일 주소가 아직 사용되지 않은 경우 계정 생성을 명시적으로 확인해야 합니다.

    계정 설정에서는 연결된 ID를 확인하고 공급자 연결 또는 연결 해제를 수행할 수 있습니다. 최소 하나의 연결된 ID를 유지해야 합니다.

    워크스페이스 및 서비스

    서비스는 정책의 네임스페이스입니다. 새 계정에서는 서비스 워크스페이스를 열고 서비스 이름에 books를 입력한 뒤 서비스 생성을 선택합니다.

    첫 번째 인가 정책 생성

    에디터에 다음 SPDL 문을 입력합니다:

    grant user alice from corp get /books

    from corp는 이 인가를 corp ID 도메인 내로 제한합니다. corp를 애플리케이션이 신뢰할 수 있는 인증 데이터에서 파생하는 도메인으로 대체하고, 아래 플레이그라운드 예제처럼 각 요청에서 주체의 idd로 동일한 값을 전송하십시오. "from"이 없는 인가는 모든 도메인의 alice라는 이름을 가진 사용자와 일치합니다. 도메인 간에 이름 충돌 가능성이 없는 단일 ID 소스를 가진 서비스의 경우에만 이 절을 생략하십시오. 규칙 및 해당 요청 필드에 대해서는 ID 도메인을 참조하십시오.

    정책 검증을 선택하고 콘솔에 식별 결과: 인가 정책으로 보고되는지 확인한 다음 정책 저장을 선택합니다. 검증에서는 정책 타입을 감지하고 구문을 확인하지만 초안은 저장되지 않습니다. 저장은 독립적인 수동 작업입니다.

    플레이그라운드에서 인가 결정 테스트

    플레이그라운드를 열어 정책을 테스트합니다.

    요청의 주체에 프린시펄을 입력합니다:

    {"type":"user","name":"alice","idd":"corp"}

    작업에 get, 리소스에 /books를 입력합니다. 평가를 클릭하면 결과는 allowed: true(이유 코드 0)가 됩니다.

    프린시펄의 idd를 other로 변경하거나 리소스를 /secret으로 변경하면 요청은 거부됩니다(allowed: false).
