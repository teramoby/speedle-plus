Speedle Cloud API 키

    API 키는 계정에 속하며 범위에 따라 해당 계정의 서비스에 접근합니다. 최종 사용자가 아닌 애플리케이션을 인증합니다. API 키, 세션, 연결된 신원 관리에는 로그인한 콘솔 세션이 필요합니다.

    Speedle Cloud는 출시 예정입니다. 이 가이드는 프로덕션 로그인과 인증된 인가 API가 제공될 때의 사용 절차를 설명합니다. 예제는 실제 Cloud 환경에서 실행하지 않았습니다.

    API 키 생성

    API 키에서 앞뒤 공백을 제외한 1–128자 이름, 범위, 만료 기간(7d, 30d, 90d, 180d, 365d. 콘솔 기본값은 3개월)을 지정하고 생성을 선택합니다. 생성하려면 최근 10분 이내에 연결된 제공자로 인증해야 합니다. 403 reauth_required이면 다시 인증한 뒤 생성을 다시 선택하세요. 제공자에서 돌아오는 것만으로 생성되지 않습니다.

    키마다 생성 후 변경할 수 없는 범위 하나가 있습니다.

    범위 접근 권한
    ads (기본값) /authz-check/v1/* 인가 검사만 가능.
    pms:read /policy-mgmt/v1으로 계정의 서비스, 인가 정책, 역할 정책 읽기.
    pms:write /policy-mgmt/v1으로 계정의 서비스, 인가 정책, 역할 정책 읽기, 생성, 삭제.

    관리 범위는 ADS를 호출할 수 없으며 ads는 정책을 관리할 수 없습니다. 범위가 맞지 않으면 403 insufficient_scope입니다. 로그인이 닫혀 있을 때 관리 범위를 요청하면 403 management_scope_disabled입니다.

    콘솔은 세션 인증 요청을 전송합니다.

    POST /api/tokens
Origin: https://cloud.speedle.io
X-SC-CSRF: 1
Content-Type: application/json

{"name":"books-app","scope":"ads","expiresIn":"90d"}

    요청은 name, 필수 expiresIn, 선택적 scope(기본값 ads)를 받습니다. expiresIn은 7d, 30d, 90d, 180d, 365d 중 하나입니다(1주, 1개월, 3개월, 6개월, 1년). 하루는 24시간입니다. 콘솔의 유효 기간은 기본값이 3개월이며, 제출 전에 예상 만료 시간 (UTC)를 보여 줍니다. 만료되지 않는 키는 없습니다. 서비스 선택, expiresAt, 인증 증명은 보내지 마세요. expiresIn이 없거나 알 수 없거나 클라이언트가 expiresAt을 보내면 400 invalid_request입니다. name과 scope만 보낸 요청도 같은 오류입니다. 서버가 expiresIn을 채우지 않습니다. 세션 쿠키와 CSRF 헤더가 필요하며 API 키로 세션을 대체할 수 없습니다.

    비밀 값 보호

    생성에 성공하면 HTTP 201을 반환합니다. 응답의 token 필드는 API 키 비밀 값이며 한 번만 표시됩니다.

    spdl_<canonical uppercase ULID id>_<43 base62 digits>

    모든 키는 만료됩니다. 응답의 expiresAt은 서버가 계산한 Unix 밀리초 시각입니다. 그 시각 이후 인가 확인과 정책 관리 호출은 401 {"error":"api_key_expired"}를 반환합니다. 새 키를 만드세요. 만료된 키를 다시 보내도 성공하지 않습니다. 만료 전에 폐기할 수 있습니다. 만료가 필수가 되기 전에 만든 키에도 만료 시각이 있습니다. 만든 뒤 365일(하루 24시간)이 아직 미래이면 그 시각에 만료되며, 필수화 직후일 수도 있습니다. 그 날이 이미 지났으면 필수가 된 뒤 30일(하루 24시간)입니다. 목록의 모든 키에 expiresAt이 있습니다. 그 전에 확인하고 새 키를 만드세요.

    사용 가능한 키가 아닌 형식 설명입니다. 즉시 서버의 비밀 저장소에 보관하세요. 브라우저 저장소, 프런트엔드 코드, URL, 소스 관리, 스크린샷, 로그에 넣지 마세요. 목록에는 메타데이터만 나오며 잃어버린 값은 복구할 수 없습니다.

    계정의 모든 범위를 합쳐 활성 API 키 10개까지 가능합니다. 추가 생성은 409 {"error":"quota_exceeded","limit":10}을 반환합니다. 사용하지 않는 키를 폐기하거나 만료될 때까지 기다려 자리를 확보하세요. 한도는 주기로 초기화되지 않습니다. 폐기된 키와 만료된 키는 목록에 남지만 한도에 포함되지 않습니다.

    API 키 목록

    GET /api/tokens는 활성, 만료, 폐기된 키를 최신순으로 반환합니다. 기본 페이지 크기는 25이며 limit은 1–100입니다. 응답의 nextCursor를 다음 cursor로 보내고 null까지 반복합니다. 각 키는 Unix 밀리초 expiresAt을 포함합니다. 콘솔은 만료 시간 (UTC)를 표시합니다. 7일 이내에 만료되는 키는 곧 만료됨으로 표시됩니다. 만료된 키는 만료됨 그룹에 나옵니다. lastUsedAt은 최선형으로 보통 시간당 최대 한 번 갱신하므로 미사용의 증거가 아닙니다.

    API 키 폐기

    폐기를 선택하고 이름과 ID를 확인합니다. 폐기에는 최근 재인증이 필요하지 않습니다. 콘솔 요청은 다음과 같습니다.

    DELETE /api/tokens/<API key id>
Origin: https://cloud.speedle.io
X-SC-CSRF: 1
Content-Type: application/json

{}

    첫 폐기는 본문 없는 HTTP 204입니다. 알 수 없거나 다른 계정의 ID, 이미 폐기된 ID는 404 not_found입니다. 이미 검증된 인증 정보는 최대 60초간 유효할 수 있으므로 모든 위치에 즉시 반영되지는 않습니다.

    지원 작업은 생성과 폐기입니다. 값, 범위, 만료 기간을 바꾸려면 새 키를 만들고 호출자를 변경한 다음 이전 키를 폐기하세요. 한도에 도달했고 모든 키가 사용 중이면 폐기 전에 중단을 계획하세요. 서비스를 삭제해도 계정 API 키는 폐기되지 않습니다.

    응답이 유실되면 목록을 새로 조회한 뒤 조치하세요. 이름이 같아도 잃어버린 비밀 값을 복구할 수 없습니다. 제한과 오류 및 인가 API를 참조하세요.
