전역 역할

워크스페이스의 모든 서비스가 공유하는 역할 할당입니다.

    Speedle Cloud는 공개 베타로 제공 중입니다. 이 가이드는 실제 서비스에서의 사용 절차를 설명합니다.

    역할 할당은 보통 하나의 서비스에 속합니다. 같은 워크스페이스의 여러 서비스가 같은 할당을 공유할 때는 워크스페이스의 전역 역할 서비스에 한 번 정의하고 각 서비스의 인가 정책에서 그 역할을 사용합니다.

    전역 역할은 역할 정책만 허용합니다. 전역 역할 할당 자체는 어떤 작업도 허용하지 않습니다. 허용할 권한은 여전히 각 서비스가 정의합니다. 전역 역할은 하나의 워크스페이스에 속하며 워크스페이스 간에 적용되지 않습니다.

    역할 할당을 한 번 만들기

    콘솔 서비스 선택기 맨 위에서 전역 역할을 선택하고 역할 정책을 만듭니다.

    grant user Emma from corp AdminRole

    from corp는 할당을 corp ID 도메인으로 제한합니다. 생략하면 요청의 도메인에 관계없이 Emma라는 이름의 모든 사용자가 일치합니다. ID 도메인을 참조하십시오.

    이제 AdminRole 역할이 워크스페이스의 모든 서비스에서 Emma에게 할당됩니다.

    서비스에서 권한 부여하기

    권한이 필요한 서비스(예: library)로 전환하고 인가 정책을 만듭니다.

    grant role AdminRole borrow books

    이 작업을 허용해야 하는 각 서비스에서 이 단계를 반복합니다. 자체 인가 정책이 없는 서비스는 역할이 할당되어 있어도 아무 권한도 부여하지 않습니다.

    결과 확인

    library의 Playground를 열고 [{"type":"user","name":"Emma","idd":"corp"}]을 주체, books를 리소스, borrow를 작업으로 테스트를 실행합니다. AdminRole을 통해 허용됩니다. Bob의 같은 요청은 거부됩니다.

    전역 역할 자체의 Playground는 다릅니다. 전역 서비스 자체에 대한 판정은 항상 거부됩니다. 전역 역할은 각 서비스의 Playground에서 적용됩니다.

    동작과 제한

    • 전역 역할은 역할 정책만 허용합니다. 전역 서비스에서 인가 정책을 만들면 400 {"error":"global_authz_unsupported"}를 반환합니다.
    • 전역 서비스는 워크스페이스의 서비스 한도에 포함되고, 그 역할 정책은 워크스페이스의 합산 정책 한도에 포함됩니다. 제한과 오류를 참조하십시오.
    • 콘솔은 이 특별한 서비스를 전역 역할로 표시합니다. 직접 만들거나 이름을 바꾸거나 삭제할 수 없습니다.
    • 워크스페이스의 각 Speedle Cloud ADS 인스턴스는 선택한 서비스 집합만 동기화하더라도 항상 전역 역할 정책을 받습니다.
    • 변경은 다른 정책과 같이 전파됩니다. 게시된 스냅샷을 통해 약 1분, 현재 상태를 직접 읽는 Playground에서는 즉시 적용됩니다.
