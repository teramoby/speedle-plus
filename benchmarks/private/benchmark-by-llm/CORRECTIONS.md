# 结论与交接描述的修正

以下修正发生于测量完成后的审阅/讨论阶段，不改变原始性能数据，不增加未执行的测试。

1. **关系授权能力。** 原交接将Speedle+路径编码样例的限制扩大为产品能力限制，初稿也据此对通用图关系能力作了过宽比较。用户指出attribute、role hierarchy、custom function均可实现相应关系授权；官方[SPDL](https://speedle.io/docs/spdl/)与[自定义函数](https://speedle.io/docs/custom-function/)说明支持这些机制。报告现将等价关系建模标为未覆盖，不再以路径样例判断Speedle+不能支持这些需求，也不据此推荐OPA优于Speedle+。
2. **角色继承已验证。** 本轮s2角色继承三引擎均4/4通过。普通角色继承不应列为Speedle+缺项。
3. **版本现状。** 2026-10-29查询中，v1.6.0已出现在GitHub release与Go代理中；“没有可识别正式Go版本”的旧说法已过时。本轮仍锁定b276伪版本，不推断新版本行为。
4. **文档现状。** 查询时当前README已改用go install/go build。固定旧版本README与仍含dep、旧Istio Mixer步骤的页面分开评价。
5. **旧数字和排序。** 原shrek数字只为历史参考，不混入charming报告，不预设排序；5次/3轮按原规则全部保留，没有为符合旧结论筛选结果。
6. **内存口径。** 原加载表列名MB实际按2^20字节计算；报告按MiB解释，为保留Go堆增量，不是进程RSS或峰值内存。
7. **阶段HTTP。** 用户索取进展时展示的是首轮数据；完整报告和summary现统一为三轮中位数。没有以首轮冒充最终结果。

对于扩展关系授权，后续若要判断维护成本、端到端延迟和一致性，应实现等价语义后另行评测。本归档没有这部分新实验。

8. **归档期间的后续文档修复。** [PR #133](https://github.com/teramoby/speedle-plus/pull/133) 于2026-10-29 10:59（Asia/Shanghai）合并，更新嵌入部署说明的Go modules/current Go步骤。这晚于上午约09:24的页面采集和测试报告初稿。报告保留历史观察并加时间注记，不把它继续列为归档时的现存问题；固定b276运行时行为与性能数据不变。
